The signed publication Review area includes a separate finite analytics schedule card. Selecting a completed publication, rendering the card, changing a project or role, and opening Studio do not read providers or create plans. The existing human publication-review capability exposes the card; Native Session fields and both default-disabled collector/scheduler gates stay unchanged.

Read the selected publication's original receipt and operator configuration explicitly. A new plan fixes the report dates, account configuration, publication/receipt hashes, aware start/deadline, maximum runs, interval, per-read consent time and bounded retry count. Read-only consent and background-read consent have separate checkboxes. Protocol mocks require their own acknowledgement and stay labelled as simulations. Multiple attempts require explicit retry consent. The backend validates the window against current Owner and OAuth expiry; Studio cannot enable the runtime or renew either authority.

History and stored-plan reads show finite status, admitted count, next due, original child reads and immutable observations. Zero remains zero; missing/unsupported metrics remain unavailable. Expired history needs no current account configuration or new consent. Historical cancellation remains available to the current Owner after project edits, archiving or active analysis, with an explicit choice to keep the already admitted read or stop it. Cancellation binds the exact policy and version and stops future admissions. Unknown cancellation responses require an explicit stored-plan read before deciding what to do next.

Selection, workspace, project, revision, archive, dirty state, active work and role changes invalidate visible consent and late responses. Same-project finite request keys survive selection/revision/role changes, new-request preparation, successful creation and uncertain replies. An exact retry keeps the key even after the planned start has passed; the server decides stored replay versus expired new admission. Distinct forms get distinct keys. History is scoped and bounded; cursor values are opaque and encoded. No automatic read, polling, publishing, budget change, canonical edit or media replacement occurs.

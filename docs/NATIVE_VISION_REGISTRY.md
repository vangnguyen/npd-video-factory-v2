# Native protected Vision configuration

The Native Vision factory now resolves dedicated workspace-bound credentials from immutable Windows DPAPI storage outside the source checkout and state backups. This is configuration and credential architecture. Current human approval, rights validation and project budget admission still belong to the runtime caller and are not granted by a factory, receipt, registry or key.

`NativeVisionKeyVault` stores each explicitly supplied key as a new `nviv_` generation. Dedicated entropy binds the workspace. The encrypted envelope binds its reference, alias and hashed key identity. Current-user and SYSTEM protected ACLs are applied before bytes are written; Windows atomic rename refuses replacement. Public receipts contain bounded size and cipher/binding hashes, with raw false authorization markers. Keys are excluded from model representations, errors, public receipts and backups. No actual provider credential was supplied in verification.

Construction, registry discovery, public status and startup recovery never decrypt credentials or create a missing vault. A mounted cipher is hash-checked, not described as a verified provider credential. Changing the vault, profile, registry bytes, workspace, operator switch, mock mode or transport invalidates the frozen configuration. Relative/source/state paths, links and hard links are refused. Private resolution rechecks receipt, encrypted metadata, inner key identity and file binding before returning a key internally.

The protected public registry has schema `native-vision-registry-v1`, version 1, one workspace and at most eight uniquely identified/aliased profiles. Profiles use the existing `openai-vision` adapter and `gpt-5-mini` model. Monetary values require explicit finite VND decimals, at most six fractional digits, without boolean or float coercion. Real configuration requires positive estimate, input and output token rates. A separately enabled operator switch and an enabled profile are necessary. Neither switch is human paid-operation approval.

The factory uses the existing `NativeEvidenceFrameExtractor` and shared structured adapter. Its configuration discovery is inert; provider construction checks the frozen source binding and grants no runtime authority. Private resolution happens only when the caller invokes the adapter. Explicit contract transport accepts exactly `httpx.MockTransport`; its mock identity stays frozen and is reported separately from real provider acceptance. Original source metadata, actual PNG dimensions and requested-seek timestamp limitations are preserved. No continuous tracking, decoded timestamps or genuine semantics are inferred by this configuration layer.

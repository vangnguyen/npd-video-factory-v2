# Native official resumable worker

Master Spec sections 45–47, 52 and 55/56 and original Wave 9 remain authoritative. This increment completes the owned Native dispatch/session/worker prerequisite for YouTube execution using existing provider protocols. It remains disconnected from accepted runtime HTTP/Studio and automatic worker selection. The later [lifecycle increment](NATIVE_OFFICIAL_PUBLISH_LIFECYCLE.md) adds explicit consent renewal, pre-secret read backoff and interrupted-cost recovery. Protected publishing credentials/refresh, scheduling, remaining platform runtimes, authentic analytics and real-provider/Owner acceptance remain outstanding. Publishing defaults remain disabled.

Each initialization, data chunk or status reconciliation commits a scoped versioned intent before its mutating wire request. Concurrent initiation is fenced; the same publication can have only one initialization intent. An uncertain initialization retains the artifact duplicate guard and requires review. An uncertain chunk retains its known private session and acknowledged offset and permits only reconciliation against that same session. Restart recovery records interrupted intents without provider calls or creating a replacement session. Current Owner identity/grant, workspace/project, immutable review, account/configuration and physical final artifact remain mandatory before dispatch.

Acknowledgements must be monotonic, within a previously sent byte window and aligned to the existing 256 KiB chunk protocol. Completion requires a sent final range and the exact total bytes plus valid returned video identifier. Reconciliation cannot invent unseen progress. A bounded Retry-After value becomes a durable local backoff. Session expiry and hard failures retain the duplicate guard and require review. No remote cancellation or deletion is performed.

The returned upload URI is sealed under Windows DPAPI with a separate session domain. Scope, review, target/configuration fingerprint, mock mode, total bytes and expiry are inside the protected envelope and are checked against SQLite and current admission. Files have private ACLs and live outside source and project state. Public receipts contain an opaque reference and ciphertext hash; they contain no URI, bearer, credential or private path. Construction/status never decrypts. Missing, corrupted, expired, rebound or wrong-domain state fails closed. A known response arriving after consent expires is retained encrypted and blocked from sending further bytes. Loading a project backup cannot supply missing secrets or restart an upload.

The worker performs one explicit bounded step. It checks the currently authenticated YouTube channel, then initializes once, sends one exact physical-artifact chunk, or reconciles the existing URI. It rechecks current admission and credential identity around each call. Official requests remain bounded and use the existing fixed-origin, no-redirect/no-retry transport. Every read and upload operation has a distinct durable cost intent. Mock mode and external execution are frozen separately. Unknown estimated and billed costs remain null; no zero receipt is invented.

An uploaded video alone has no publication receipt. A separate processing read must observe successful processing and the requested privacy before a terminal receipt exists. Observation history is append-only. Receipts bind the immutable publication request, workspace/project/review and returned remote identifier and preserve mock/external flags. No remote URL is guessed. Pending processing, visibility mismatch, stale source/grant or altered receipts cannot be presented as completed real publication. Future scheduling and consent renewal across long processing periods still require integration work.

Additive SQLite journals retain intents, selected response evidence, opaque session metadata, processing observations and receipts alongside the existing review/approval/event/dispatch tables. Native backup counts all journals and blocks queued/running official work. The retained rehearsal restores a completed mock receipt, all ten publication/cost tables, unchanged fixture projects/jobs/artifacts and an unconfigured vault. It verifies fresh-process replay without any dispatcher/credential activation. Private DPAPI files and upload URIs do not enter the archive or exported evidence. This is a workflow-database rehearsal; prior increments separately preserve both databases and genuine prior video bundles.

Tests use explicitly nonplayable media and synthetic QC, rights, identity, channel, capability and official wire fixtures. Actual local tests cover Windows DPAPI/ACLs, SQLite fencing, scope/tamper/expiry, concurrency, interruption, exact chunking, same-session reconciliation, cost history, terminal processing/privacy, backup and fresh-process restore. They establish neither legal rights nor actual media QC, account ownership, real provider behavior, signed HTTP/Studio usability or Owner acceptance.

Protocol reuse follows official [resumable upload documentation](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol), [video insertion](https://developers.google.com/youtube/v3/docs/videos/insert), [channel verification](https://developers.google.com/youtube/v3/docs/channels/list) and [processing/status reads](https://developers.google.com/youtube/v3/docs/videos/list).

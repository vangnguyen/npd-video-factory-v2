# Reviewed Vision in storyboard Media Planner

Storyboard Media Planner can now use an explicitly reviewed successful Native official Vision result. An editor first selects the completed result in the Assets Vision card, chooses “Chọn kết quả Vision đang xem” in Media Planner, and acknowledges having reviewed it. A protocol mock requires its own acknowledgement. Only creating a new plan submits the selected original intent/snapshot/result hashes; choosing a result, reloading, or changing controls performs no provider request. Applying a choice to a shot remains a separate confirmation that invalidates approval and uses the existing canonical timeline.

The native-reviewed-vision-context-v1 projection is reconstructed from the original validated official Vision journal, using the caller's transaction. Current reuse binds the actual asset bytes, CPU frame observation and PNG hashes, original scene/transcript context and input binding. Saved history revalidates the original result/response/cost lineage without decrypting a key, renewing the original finite consent, consulting a current enabled connection, or dispatching a job. Raw boolean acknowledgements, duplicate/foreign selections, incomplete outcomes and changed hashes/source are refused. Canonical JSON hashes distinguish numeric 0/1 from raw false/true in saved projections and candidate attribution.

New optional reviewed plans use native-storyboard-media-plan-v2 / native-storyboard-media-planner-v3. Plans without a selection continue to use the existing v1 schema/v2 algorithm. Original v1 algorithm history remains exact and read only. Reviewed provider labels use lexical overlap rather than an embedding or claimed semantic calibration. Predicted sampled quality is explicitly uncalibrated; candidate confidence remains null. Full frame/scene/prediction/source evidence is retained in the plan input, with original response, cost and consent timestamps. Every explicit mock contributes no semantic tokens or provider-quality score. Revised reviewed queries recompute their visible candidate scores; saved scores and compact lineage are rechecked against the original projection, so rehashing cannot promote a mock into provider ranking.

The existing rights/selectability, missing-price, budget, separate stock/generation execution and canonical apply gates remain enforced. A reviewed result does not authorize payment, publish a video, create crop tracking, prove decoded source PTS or replace full media QC. A current-source change blocks reuse/application while original plan history remains readable. The UI clears local review acknowledgements when project, revision, access, dirty/busy/active state or the selected Vision result changes. Provider analysis acknowledgement is not reused as planning or timeline approval.

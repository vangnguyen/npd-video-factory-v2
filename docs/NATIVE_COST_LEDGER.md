# Native project costs

The completion branch adds a cost summary to the Native Studio Video stage. The Native server advertises `native_cost_ledger`; older servers do not load the optional module or request its routes. Missing billing data is shown as “Chưa rõ.” Known subtotals, estimates and budget reservations are separate from billed spend. Totals cover recorded operations only; prior history and local compute costs are not certified.

`GET /api/projects/{id}/cost-summary` requires the existing local session. `POST /api/projects/{id}/cost-policy` additionally requires CSRF and the current project revision, with exactly `revision` and `max_ai_cost_vnd`. The amount is VND, nonnegative and finite; null removes the optional limit. Saving creates a version and invalidates production approval. Busy/archived/stale projects retain their existing edit protections. These local-session checks do not replace the remaining multi-user RBAC work.

The additive `native_cost_operations` table belongs to the existing Native workflow database. No historical records are invented. A committed dispatch intent records project, optional job, provider, model, operation, request hash and nullable estimate before the provider call. Project/job bindings and concurrent admission are validated in the same SQLite transaction. Under an explicit limit, unknown or excessive estimated exposure blocks a paid operation before dispatch. A missing limit preserves the existing provider authorization path; cost admission itself never grants credential, rights, publishing or paid-provider authority.

Content-generation attempts, live shot-edit suggestions and actual AssemblyAI upload/create/poll wire calls are metered. Mock replacement providers are not silently promoted into external billing evidence. Existing intent/checkpoint rules continue to prevent write replay, while known ASR jobs may be observed through new read operations. Lost responses remain unresolved, and token counts never become billed VND. A paid actual-cost record requires a separately bound billing-receipt hash; the current production adapters leave actual cost null because no billing receipt is supplied. Receipt replays are exact, changed terminal receipts reject, and no public reconciliation/override route is exposed.

Unknown estimates currently block budget-constrained paid operations; a configured price/admission estimate path remains to be completed. Intelligence operations before project creation, all stock/Vision/generative paths, uniform provider/job capture, historical billing reconciliation, production RBAC and whole-project billing coverage remain open. Budget holds are conservative; unresolved attempts cannot be retried to recover money automatically. Provider account review remains a separate human action.

Verification uses isolated SQLite and explicit synthetic money/provider fixtures. It includes restart, scoped records, concurrent admission, pre-dispatch refusal, lost-response no-replay, receipt immutability, CSRF/session/stale checks and Studio escaping/legacy capability guards. `scripts/north_star_native_cost_contract.py` produces a fresh six-file persistence bundle. It does not contact a provider, spend money, publish, accept Owner UAT or certify deployment.

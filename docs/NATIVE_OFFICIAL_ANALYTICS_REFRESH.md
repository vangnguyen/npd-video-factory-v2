# Finite official analytics refresh

Native now has a separate finite scheduler over its receipt-bound official YouTube analytics collector. Both the collector and scheduler gates default off. Explicit operator configuration requires the existing protected read runtime and human authentication. `--enable-official-analytics-refresh` also requires `--enable-official-analytics`; it does not enable publishing, create credentials, renew consent or decrypt tokens at startup.

An Owner creates a versioned immutable plan for one completed publication and its original snapshot/receipt hashes, exact account configuration, fixed report query, current identity revision, aware start/deadline, interval and maximum read count. Read-only, background-read, protocol-mock and bounded-retry acknowledgements are distinct raw booleans. Maximum runs are 1–100, interval 60–86,400 seconds, and each read consent 60–3,600 seconds. The plan window must fit the current Owner and explicitly resolved credential expiry. Credential proof retains expiry, scope and target hashes, with no bearer token. Default-disabled/not-configured plans never resolve credentials or start later automatically.

The worker admits one occurrence at a time in the same workflow transaction as the existing collector request. Deterministic scoped keys, original consent/request/policy hashes and bounded ordinal/due/admission times bind the occurrence to its source. Each child consent is capped to the plan deadline at the actual admission time. Admission failure or Owner revocation after child insertion rolls back both journals. A later next due is based on actual admission, so missed intervals do not produce a catch-up burst. Existing pending manual or scheduled reads prevent another read for the same publication.

Each occurrence reuses the original collector's account/video ownership/report requests, response/cost proof, expiry/Owner/account/source fences, approved retry/backoff and immutable normalized snapshot. A known retry stays within that occurrence. Failed, cancelled or uncertain results stop the plan for review; a restart never reissues an unknown read. Exhaustion completes a successful finite plan. Deadline, account drift, credential-proof change or revocation prevents further admission. No new snapshot store, fabricated metric or second provider path is introduced.

Cancellation needs a current Owner, exact policy SHA and version, and an explicit choice about the admitted read. Keeping it allows that already consented read to finish; cancelling it uses the existing collector cancellation fences. Both choices stop future admissions and preserve original intentions, responses, costs and history. No remote deletion or token/session reset occurs. Historical plan/occurrence/snapshot reads validate original sources without current credentials, Owner authority or provider factories, including after archiving and expiry.

Signed routes are `/api/connections/official-analytics-refresh` and `/api/projects/{project_id}/official-analytics-refresh` with scoped history/detail and an Owner-only `/noap_{id}/cancel` action. Roles and CSRF are checked before the bounded body. No authority, credential, endpoint or runtime-enablement field is accepted from requests. Native Session capability fields stay unchanged. Worker logs identify project/job/stage/provider/duration without tokens or private content. Three additive plan/occurrence/event journals join backup inspection; active plans prevent a quiescent backup. Agent Hub receives the existing separately versioned qualified analytics source events only after successful collection, with webhook delivery still default off.

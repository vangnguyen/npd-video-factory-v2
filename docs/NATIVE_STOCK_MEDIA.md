# Native stock media intake

The separate [Owner exception workflow](NATIVE_OWNER_RIGHTS_OVERRIDES.md) now provides default-disabled, expiring legal-decision architecture. It retains actual stock provenance and cannot promote provider fixture media. Genuine asset-specific decisions and real-provider acceptance still require Owner/provider evidence.

The Assets stage now connects the existing provider-neutral stock contract and official Pexels/Pixabay adapters to Native Studio. This is search, download, local validation, review and explicit project attachment. It does not automatically place media, verify third-party rights, enable publishing or replace an accepted artifact.

Both providers are `NOT_CONFIGURED` by default. `--stock-provider-registry` reads a strict version-1 JSON file outside the state root, with `native_workspace_id` and optional `pexels`/`pixabay` objects containing `api_key` and `enabled`. Loading the file does not enable calls; `--enable-stock-api` is also required. No browser endpoint can read/write keys, change this configuration or turn it on. The file is read once, with bounded size, duplicate-key rejection, path/link checks, exact workspace and secret-safe failure codes. Credentials are neither persisted in project/job/evidence data nor sent to CDN requests. Production ACL/provisioning/rotation remains part of hardening; no real registry was loaded during this increment.

The reused adapters implement `search_images`, `search_videos`, `get_asset` and `download_asset`. They use authorized JSON APIs and approved HTTPS media hosts, bound response sizes/timeouts, prohibit redirects and arbitrary client URLs, and re-fetch a selected asset by canonical provider ID before downloading. API responses cache for 24 hours under a digest of the actual Native root and workspace. Restoring terminal evidence does not enable adapters or let a different root use the old scope. Provider/creator/source/license/attribution are retained; unavailable semantic and Vision ranking scores stay null. The current [Pexels API documentation](https://www.pexels.com/api/documentation/) specifies authorization, photo/video endpoints, source attribution and quotas. The [Pixabay API documentation](https://pixabay.com/api/docs/) specifies its photo/video API and caching guidance. Retained content license references are [Pexels](https://www.pexels.com/license/) and [Pixabay](https://pixabay.com/service/license-summary/); API access or a content license does not establish independent third-party clearance.

`GET /api/stock/providers` reports provider status and execution mode without credentials. Scoped `GET /api/projects/{id}/stock` and `/{stock_id}` expose bounded history and immutable snapshots/results. Owner-only `POST .../stock/search` and `/download` require the saved project revision and an explicit source acknowledgment. A download selects a saved search ID, candidate ID and exact result/candidate digests. Clients cannot supply a URL, provider result, license, rights status or cost. Strict DTOs distinguish an actual API acknowledgment from an injected wire-fixture acknowledgment; default missing providers never create fixture results as a fallback.

The additive `native_stock_bindings`, `native_stock_jobs`, `native_stock_events` and `native_stock_imports` tables remain inside Video Factory's owned state. Persistent workspace binding rejects empty-root or existing foreign state before a request. Request-key retries keep the original job/result; changed requests conflict. Snapshots freeze project/document, query, selection, provider configuration and cache scope. Before dispatch, the worker verifies current revision/document and the exact parent selection/configuration. Jobs have fenced claims, a bounded lease, at most three read-only attempts and bounded backoff. Queued/retrying requests can be cancelled. Expired claims record interruption rather than silently inventing a response. Provider result corruption or fixture promotion fails closed.

An independent stock worker does network and media work outside the project transaction and renderer queue. A deliberately stalled wire mock leaves an unrelated core job free to complete. Each dispatched attempt uses the existing Native cost ledger, provider/model/operation/request binding, estimated API cost and a response digest. These are non-pipeline jobs, so the ledger's pipeline `job_id` is null and its operation carries the Native stock job/attempt ID; the stock result retains `cost_operation_id`. Billed and local compute costs remain unknown without a receipt; an estimated free API operation is not a fabricated charge. Paid operations are zero.

Downloaded bytes pass existing Native MIME/magic, full image decoding or FFprobe/full video decoding/thumbnail limits before being registered as staged media. Actual dimensions/duration and normalized/source SHA256 remain distinct from provider metadata. Original bytes are retained. Staging does not alter project approval, canonical timeline or asset selection. Failures clean only newly created unregistered files. The local review file route verifies exact normalized/source bytes and serves media through the authenticated scope; the browser does not load provider download URLs.

Editor/Owner `POST .../stock/{stock_id}/import` requires a fresh revision, exact saved request/media hash, acknowledgment and key. It reuses the existing upload attachment transaction. Project/history/approval invalidation, immutable attachment receipt and audit event commit together; retries return the frozen version-bound receipt. Read-only users cannot attach. Attachment does not choose a shot or place B-roll. The existing Assets/shot/timeline controls remain canonical. Stock B-roll projections preserve the actual stock provider/source/license/generation metadata and unknown/restricted declaration status instead of treating stock as a verified user upload. Legacy explicit upload-attestation behavior remains separate and is not independent license verification.

Wire mocks are test-only injected factories, with no fixture option in the live registry or automatic fallback. Mock results remain marked throughout search/download/history/provenance; staged fixture media has `rights_status=unknown`, `production_eligible=false`, `needs_attention=true`. Official adapter materialization retains the provider content license but also requires review (`production_eligible=false`). Neither path grants an Owner legal override. Unknown rights and ineligible assets block publishing by default. A legal review/override workflow and real-provider acceptance remain open.

The capability-gated Assets panel has explicit configuration/history reads, source/format/query selection, per-request acknowledgment, saved candidate/digest selection, bounded progress reads, cancellation, local image/video review and explicit attachment. Provider/source links and creator text are visible. Literal text, stable lost-reply keys and workspace/project/revision/role/dirty/busy/archive/active guards are tested. UI/DOM contracts do not certify an actual browser, viewport, non-developer or Owner UAT.

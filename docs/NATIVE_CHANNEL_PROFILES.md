# Versioned Native channel and niche profiles

New Native projects can explicitly choose a channel profile in the existing Studio creation form. The versioned catalog has technology/AI education and property reference channels. Typed `ChannelProfile`, `NicheProfile`, publishing preferences, analytics preferences and Source preferences reference the existing content, brand, video and subtitle catalogs. Niche keys are configuration strings; the production core has no channel-ID-to-niche mapping. The reference profiles retain the certified local voice fingerprint and do not select a new paid provider.

The server resolves catalog references and atomically freezes the complete channel definition, niche, audience, language/locale/country, keywords/tone, content profile, brand/template, Source subtitle style/audio/default preview mode and their hashes into the new project. Publishing stays disabled, unknown rights block, human publish approval remains required, account/credential references stay unavailable and analytics defaults to unconfigured official reads with missing metrics null and recommendation-only learning. These are typed preferences, not configured official accounts or live runtime enablement.

Project reads validate the frozen selection. Source timeline creation binds the selection digest and applies its declared subtitle/audio/effects-preview defaults to the canonical timeline. Source validation rejects altered snapshots or timeline bindings. Source rendering takes niche and brand metadata from saved configuration. Current Source edits can still change captions/audio/format through the existing versioned canonical editor, with fresh preview/approval gates. Narrated projects reuse the existing brand/template engine. Frozen channel choices are initial defaults; current explicit editorial choices are separate saved state. Source logo/brand overlays, additional voice/provider selection and full channel runtime integration remain gaps.

Existing projects without a channel selection retain their behavior. Catalog changes/removal do not replace a saved profile during reads. Generic copies and source variants retain frozen configuration while preserving their independent timeline/review/source identity boundaries. Creating a project cannot submit an arbitrary profile body: only a configured versioned reference is resolved. A conflicting content-profile choice rejects without creating the project. No profile selection queues research, ASR, TTS, generation, publishing, analytics or paid work.

The Studio selector is capability gated and loads only static configuration. Literal-text options fill the visible content, brand, template, format and duration controls only after a user's explicit selection. Users can adjust those fields before creation; manually changing the content profile clears the channel choice to avoid conflicts. Existing projects show their frozen profile without applying defaults. Busy/read-only controls, stale catalog reads and publish/analytics contradictions are guarded. This DOM coverage is not a browser/viewport or non-developer acceptance session.

The fresh `native-channel-profiles-contract-n1` rehearsal makes nineteen authenticated requests, selects each profile through project-creation HTTP, uploads actual fresh synthetic footage/tone, imports an explicitly saved ASR fixture and performs real local scene/audio/eight-frame analysis. Both profiles use the same Source timeline/preview/render/QC path. Their niche and brand metadata come from the frozen profile; no manual niche seed is used. Each fresh effects preview builds scoped PCM and its independently approved fixture final render reuses it. Exact source/configuration/project version/media state survives separate-process and checksum-anchored fresh-root recovery.

The common source, captions and Source preferences intentionally produce identical final video hashes; different niche/brand metadata does not imply different visible branding or measured audience performance. The rehearsal does not run narrated Mode A/TTS, genuine ASR/Vision, real account/provider analytics, external publication, browser/Owner UAT or production. Unit/HTTP/DOM tests additionally cover a third niche added only in an owned configuration, immutable reads after catalog removal, bad definitions, enabled distribution/analytics rejection, conflicting profiles, source binding/corruption and authorization before body reads.

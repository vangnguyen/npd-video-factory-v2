# Native Owner rights exceptions

Native Studio now has a separate scoped Owner exception workflow. A human declaration still leaves rights unknown. An exception records the Owner's decision without replacing source/provider/license/generation evidence, marking rights verified, approving a project, enabling publishing or replacing accepted media.

The workflow is disabled by default. `--enable-owner-rights-overrides` also requires the existing human authentication registry. The browser and service API cannot enable it. Only the human Owner's `manage` permission can grant or revoke; session, origin and CSRF checks run before bounded body parsing. Readers can review history. In an unconfigured or restored process grants are disabled and historical exceptions inactive, but an Owner can revoke an existing grant without re-enabling the workflow.

`GET /api/projects/{id}/rights-overrides` returns exact workspace/project/revision, asset/media and current rights digests, immutable history, expiry and active exception. `POST .../rights-overrides/{asset_id}` takes a strict grant/revoke DTO: revision, physical SHA, current rights SHA, explicit reason/public evidence reference, acknowledgment and stable request key. Grant validity is one to thirty days. Local placement is the default scope. An additional explicit acknowledgment can admit the asset to publishing review; this does not authorize an external post. Restricted assets and provider/explicit fixture media cannot be promoted. References are retained as human evidence, never fetched; credential-bearing references and arbitrary extra permission/verification fields are rejected.

Records are versioned, hashed and bound to the workspace, project and physical asset. Approval invalidation, immutable project version, content-free approval-required event and idempotency receipt commit atomically. Retries return the original version-bound receipt after later edits, revocation or disabling; changed requests conflict. Grants, revocations and history are never silently overwritten. Rehashed malformed/scope/expiry/verification records fail closed. Derived projects discard foreign exception scope while preserving physical restrictions. New declarations or changed rights/source/license/generation metadata invalidate an older exception through the exact rights digest.

The Native B-roll selection/apply consumers can use an active local exception while retaining `rights_status=unknown` and `publishing_allowed=false` in their provenance. Expired, revoked or disabled exceptions do not authorize a new placement. The Native publication validator uses a distinct `RIGHTS_EXPLICIT_OWNER_EXCEPTION` check and retains original unknown-rights/production metadata plus the exception ID/hash/expiry; it never claims `RIGHTS_VERIFIED`. Every used asset is checked independently. Existing human project/final/publishing approval, immutable render/source/QC, generated voice/thumbnail, platform and default-off transport gates still apply. Expiry or disabling after approval blocks dispatch during revalidation.

The capability-gated Assets form exposes explicit configuration/history reads, literal evidence, reason/reference/days, separate publishing-review scope, acknowledgment, grant and revoke. Stable lost-reply keys and workspace/project/revision/role/dirty/busy/archived/active guards are tested. The UI has no credential, enablement, project approval or publication controls. DOM contracts do not certify actual browser, viewport, non-developer or Owner acceptance.

`native-rights-override-contract-n1` restores the prior playable synthetic bridge archive into a fresh owned root. Thirteen authenticated HTTP operations make an explicitly unverified synthetic ownership claim, test reader/editor denial, record/replay one synthetic Owner exception, disable it and revoke it, then compare the old jobs/versions/media. The original generated pixels have known fixture ownership; no uncertain real asset is legally cleared. New-process and fresh-root offline restore match and remain default-disabled. No media rerender, real provider/Hub/post, secret, paid action, actual Owner UAT or production operation occurs. Focused unit fixtures also prove publishing revalidation rejects expiry before even a mock dispatch, and actual local B-roll placement retains unknown rights then rejects reapplication after expiry.

Actual asset-specific legal decisions remain Owner actions. This architecture is implemented and mock/local tested; genuine provider rights acceptance, production secret/network controls, browser/Owner acceptance and the full original North Star remain open.

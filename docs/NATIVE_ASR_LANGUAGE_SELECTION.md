# Native Studio ASR language selection

This Wave 3B/7/8/15 component adds explicit general-purpose Vietnamese, English and automatic VI/EN language selection to the existing queued Native speech workflow. The certified Vietnamese benchmark profile, its hashes, vocabulary, context and default legacy request identity remain unchanged.

The new immutable profile family uses the existing AssemblyAI model and strict provider-native positive word intervals. General profiles send no real-estate prompt or keyterms. Explicit languages use `language_code`; automatic mode uses `language_detection` with VI/EN candidates. Candidates are hints, so the adapter validates the actual returned language and exact model instead of relabeling an unexpected response or accepting model fallback. The official request contract is documented at [Transcribe audio](https://www.assemblyai.com/docs/pre-recorded-audio/api-reference/transcripts/submit) and [Automatic Language Detection](https://www.assemblyai.com/docs/pre-recorded-audio/language-detection).

Language request, allowlisted profile and profile hash are frozen into the job snapshot and idempotency identity. Changed language conflicts under the same request key. Worker, result admission and explicit resume verify the job identity. Durable upload/create acknowledgements and known-job GET observation are reused; unknown dispatch outcomes remain non-replayable. Resuming a job with additional immutable parameters compares the original document/approval separately, fixing the prior local tracking resume mismatch as well.

Provider language, nullable language confidence and detection evidence remain separate from the requested mode. A detection request is not proof that detection occurred; `language_detection_performed` is null when the provider omits that fact. Unconfigured billing rates and unavailable billed costs remain null. Original transcript/provider response evidence is retained; English Auto Edit normalization and a versioned text edit preserve the source and original evidence, discarding unavailable edited-word alignment rather than inventing it.

The Vietnamese Assets panel exposes the legacy profile plus three new choices. Capability gating preserves older servers; each explicit choice has a separate retry key. Existing job, dirty-state and permission boundaries apply. Source analysis uses saved results, never requests another paid operation from transcript editing.

Evidence is indexed in [asr-language-selection-evidence.json](north-star/asr-language-selection-evidence.json). API contracts include both the original benchmark adapter and new profiles. Native tests use real local FFmpeg/SQLite with explicit speech-provider fixtures, including known-English-job resume, unexpected language rejection, normalization and immutable text editing. Studio tests and signed static dependency transport are separate from browser proof.

The actual in-app browser exercised all three language choices on an isolated, credential-free server with its worker disabled. Exactly one queued job per generated-tone project is preserved; no speech inference or provider upload occurred. UI screenshots and bounded dropdown geometry cover 1366/1920/2560 px for this control, not full Studio usability. The browser fixture process ended across a tool-session transition; its authoritative SQLite state was read without replay, archived and verified in a fresh process. Its owned root is retained, and no historical/accepted data was deleted.

Real Vietnamese/English/automatic ASR acceptance on genuine speech, actual full upload-to-transcript browser flow, diarization, edited-word realignment, full Mode A/B, Owner UAT, original A/B/C and production remain open. No paid/provider call, real publishing, main merge or production deployment occurred. This component does not close the full ASR requirement or change full program readiness flags.

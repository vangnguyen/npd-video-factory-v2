# Native official publication consent journal

Master Spec sections 45–47, 52 and 55/56, plus Wave 9, remain authoritative. This increment implements the Native consent and dispatch-journal prerequisite for official YouTube execution. Upload execution, encrypted resumable-session persistence, scheduling/reconciliation, HTTP/Studio integration, protected publishing credentials, other platform runtimes and real-provider/Owner acceptance remain outstanding. The accepted Native runtime continues to expose its existing four-platform dry-run workflow; no official upload worker is activated by this increment.

A separate typed publishing factory binds the existing workspace/profile/version/provider/account/credential fingerprint to category, made-for-kids and synthetic-media disclosures plus bounded chunk size. Publishing, external execution and Owner gates default false. The factory accepts the existing bounded official HTTP client and approved in-memory publishing-credential resolver; construction/public-state reads perform no token resolution or provider request. Client, transport, network mode, resolver, root, target, disclosures, gates and configuration fingerprint are frozen. Credential admission reuses the existing scoped YouTube publishing OAuth contract, including expiry and required upload/read permissions.

The official review requires a completed, still-valid Native dry-run package and a successful, current, matching account check. Neither carries official publish authority. Existing final watch/listen approval, physical render checkpoint/hash, project revision/document/approval, canonical timeline, asset/voice rights gates and platform checks are revalidated. Official mode additionally requires an explicitly Owner-verified platform capability snapshot. The repository's internal safe profile remains insufficient. Metadata/disclosures are checked through the existing pure upload protocol without dispatching its request.

The review stores an immutable request, account/result/configuration/target fingerprint, current final artifact/job/review, metadata, disclosures and validations. It contains no OAuth token or session URI. Exact retries reuse the original review, including after later project edits, while dispatch admission still requires the current artifact and document. A duplicate guard reserves the same workspace/account/final-file hash for each execution mode. A new key cannot create another active or attempted publication. An unsent cancelled or unconfigured review can be replaced without rewriting history; cancellation becomes unavailable after a dispatch intent begins. Mock and actual execution remain distinct immutable modes.

An explicit separate Owner grant binds the complete review snapshot. The journal requires a verified human Owner principal matching the current authoritative token registry, checks issuance/not-before/expiry/role, and stores an identity-revision fingerprint. Grants last 60–3600 seconds and cannot outlive the Owner token. Current identity, role, enabled state, revision, grant expiry, configuration, account proof and physical artifact are checked at dispatch admission. A dry-run approval cannot substitute for this grant. Rehashed numeric flags, invalid artifact sizes, stale data and altered fingerprints fail closed with sanitized codes.

Approval atomically creates one consent row and one prepared dispatch record. Concurrent review/approval requests cannot create duplicate records. The record binds workspace/project/snapshot/grant, total bytes, acknowledged bytes and version. No provider request occurs in this journal. Cancellation of an unsent review revokes its grant without deleting a remote post. A record with a begun dispatch requires external reconciliation instead of granting a start-over path.

Additive SQLite tables retain review, consent, event and dispatch history. Offline backup counts all four tables and rejects queued/running official work. A completed local cancellation permits snapshot/restore. Recovery does not supply missing publishing factories or credentials and cannot reactivate authority by loading historical rows. The core remains independent of API ORM, web framework, cryptography package and GPU imports.

Provider protocol reuse follows official [YouTube resumable upload documentation](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol), [video insertion](https://developers.google.com/youtube/v3/docs/videos/insert) and [processing/status reads](https://developers.google.com/youtube/v3/docs/videos/list). The next worker must persist its dispatch intent before a mutating request, protect the returned session URI, verify actual artifact ranges, reconcile uncertain results against the same session and observe processing/privacy before creating a receipt. An uncertain session start must never automatically create another session.

Tests use explicitly synthetic Owner/account/rights/QC/platform-capability fixtures and nonplayable render bytes. They cover separate consent, current identity/role/revocation/expiry, stale project/final/configuration/account proof, default disabled operation, duplicate prevention, unsent replacement, atomic concurrency, cancellation after dispatch, rehashed safety claims, strict disclosures/chunking, fingerprint identity, sanitized invalid evidence, optional backup counts and framework/GPU-independent import. These fixtures do not verify actual media QC, rights, platform limits, account ownership or Owner acceptance.

The retained local recovery rehearsal creates one separate grant and prepared record, proves pending backup rejection, revokes the unsent grant, restores exact history/project/jobs/artifacts and verifies a fresh process with no configured credentials or dispatcher. Machine evidence is indexed in `docs/north-star/native-official-publish-review-evidence.json`. It exercises the workflow database; the previous account-review increment separately verified both databases and 1,280 genuine prior media/artifact files. No HTTP/Studio/provider upload E2E, external call, paid operation, new production media job, real publication or production deployment occurs here.

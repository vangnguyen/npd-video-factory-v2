# Private evidence for rejected renders

A render rejected by Full QC keeps its original `failed_qc` / `QC_FAILED` result.
Before the worker deletes its staging directory, it can retain six diagnostic
items: the QC report, sanitized render manifest, render evidence, rejected
output bytes, mixed audio bytes, and subtitle text. The worker never registers
these as assets or fills `output_asset_id`, `playback_url`, approval, or approved
audio reuse fields. Keeping rejected bytes does not make them publishable.

The private object prefix is generated by the server:

```
workspaces/{workspace}/projects/{project}/failed-render-evidence/{render}/{attempt}/
```

`production_render_jobs.manifest_json.failed_qc_evidence` contains the versioned
descriptor. The existing production event table records the quota reservation.
No database schema or migration is added.

## Bounds and custody

The default limits use binary MiB (`1 MiB = 1,048,576 bytes`):

| Bound | Default maximum |
| --- | ---: |
| One render attempt | 32 MiB |
| One project's lifetime reservations | 128 MiB |
| Rejected video bytes | 20 MiB |
| Mixed audio bytes | 8 MiB |
| Each metadata/subtitle item | 512 KiB |
| Files per attempt | 6 |

`FailureEvidencePolicy` accepts strictly positive integers up to these ceilings.
The project writer lock serializes reservations. A deterministic reservation ID
allows one retention owner and attempt per render. Reservations commit before
object writes and remain charged after partial uploads, cancellation, crashes,
or late SQL rejection. A later delivery observes an existing reservation without
starting a second retention upload. There is no automatic refund, purge, or
recovery claim for an abandoned attempt.

The helper copies bounded source bytes into open temporary descriptors before
awaiting storage. Uploads read those descriptors; they do not reopen renderer
paths. Local storage uses an owned atomic copy. S3 uses a held body descriptor,
exact content length and SHA256, a private ACL, and the existing bounded SDK
profile. Unknown or unbounded adapters fail closed for retention. Every owned
writer drains before staging cleanup, including repeated task cancellation.
Storage failures retain the original QC error and expose a bounded retention
status code instead of SDK messages, credentials, or paths.

A failed reservation gets one metadata-only fallback with no object upload. If
SQL cannot commit either bounded terminal attempt, the worker rethrows the
original QC exception and report. It does not claim that `failed_qc` was saved
when the database still reports `running`. An uncertain committed reservation
keeps its original owner and charge; a fallback cannot steal that attempt.

Retention descriptors expire after seven days by default. Expiry blocks API
delivery; it does not delete objects or release reservations. Storage lifecycle
and reviewed cleanup remain separate operations. This feature changes no bucket
policy and deletes no accepted artifact.

## Diagnostic access

An authenticated human with access to the project can use:

```
GET  /api/v1/projects/{project}/renders/{render}/diagnostics/{name}
HEAD /api/v1/projects/{project}/renders/{render}/diagnostics/{name}
```

Allowed names are `qc`, `manifest`, `evidence`, `video`, `audio`, and `subtitles`.
The server validates the recorded failed state, project/workspace, version
context, reservation, size, hash, provider, and exact object prefix. It rechecks
the SQL snapshot after downloading and before sending headers or bytes. The
existing verified delivery implementation supplies range requests, an exact
SHA256 ETag, private temporary cleanup, `no-store`, and `nosniff`.

Rejected video/audio use conservative binary attachment types. A retained file
hash certifies byte identity only. If Full QC reported a video checksum, it must
match those physical bytes. Early QC reports without a checksum do not gain a
fabricated QC measurement.

The normal render `/content` endpoint and approval/publishing gates remain
unchanged. No diagnostic endpoint is added to the Agent Hub service facade.

## Verification limits

The focused suite exercises actual isolated SQLite, local object storage, and
ASGI delivery, including concurrent quota claims, terminal/cancellation/version
races, rollback, custody changes, byte tampering, authorization, and range
delivery. Renderer/QC outcomes in that suite are explicitly synthetic. S3 tests
use a bounded SDK stub with no wire call. They establish neither real S3
acceptance nor semantic/media quality, provider acceptance, Owner UAT, a complete
Artifact A, deployment, or North Star readiness.

# Native generated narration publication provenance

Narrated storyboard publication now has an explicit voice/model review boundary.
It uses the existing measured narration preparation, current audible preview,
production approval, final artifact review and publishing approval. Source footage
retains its existing physical source-audio path. No source schema is changed to
make generated narration appear to be source audio.

## Retained evidence

The review projects verified original narration checkpoints: exact workspace and
project, source job/snapshot, measured plan, current voice inputs, original PCM,
voice metadata, TTS plan, locked profile and model artifact manifest. The profile
retains model/codec repository revisions and card hashes, SDK/license/preset
hashes, provider and voice. Private runtime paths and narration text are excluded
from this projection. Provider license labels remain attributed evidence.

The locked voice profile still says local preset audition, human quality
acceptance pending, and watermark not installed for local audition. This change
does not alter the SDK, models, preset, voice speed, profile or these claims.
Raw voice rights remain unknown. Independent licensing and speech/pronunciation
acceptance remain false. No legal determination is inferred from a license label.

## Owner exception

The existing `--enable-owner-rights-overrides` option now also enables narration
exceptions. It remains false by default and requires configured human auth.
Native Studio exposes a capability-gated source/exception panel in Assets.
An Owner explicitly reads evidence and supplies a reason, evidence reference,
1–30 day expiry, acknowledgement and optional permission for publishing review.
The browser cannot enable the feature, impersonate an actor or supply a provider
result. Existing identity, role, origin, CSRF and rate boundaries precede bodies.
References are retained human evidence and are never fetched.

Grants bind the exact provenance digest. Explicit synthetic PCM markers cannot
qualify. Every grant/revocation is scoped, hashed, retained in project versions
and events, and has a durable request-key receipt. A changed request cannot reuse
a key. A lost browser reply keeps the same manually retried request; no automatic
POST retry occurs. The decision clears production approval without changing the
canonical timeline or audio. Current preview bindings become stale; the same
verified PCM can generate a fresh audible preview without new inference.

Revocation remains possible when disabled or when an old preparation becomes
unusable. The evidence page shows no current eligible provenance in that case,
retains history and marks the failure. It does not relax grant/publication checks.
Copies drop both prepared narration and exception authority and retain only
origin digests. No authority or acceptance transfers to another project.

## Publication validation

The publication gate checks the exact frozen exception and current history,
expiry, configuration, original source narration checkpoints, final TTS/render
checkpoints, original PCM/metadata/TTS-plan bytes, reuse receipt, rendered audio
and model/profile bindings. Revoked, expired, disabled, changed or absent evidence
leaves the generated voice gate closed. Asset rights, measured platform QC,
current production/final approval and human publishing approval remain separate.
Default `PUBLISH_ENABLED=false` and Native live adapters NOT_CONFIGURED remain.

A human exception grants review eligibility only. It does not mark rights owned
or licensed, verify a model/preset/license, accept speech, authorize a live post,
change budgets or enable a provider. Real rights/legal uncertainty and real
publishing still require the corresponding Owner action under the program.

## Validation and remaining acceptance

Tests cover exact grants and retries, scope/CAS/digest/acknowledgement, disabled
configuration, expiry, synthetic markers, changed inputs/profile/PCM/history,
revocation with unusable sources, copy isolation, rendered PCM binding and actual
HTTP role/CSRF/actor guards. DOM contracts cover manual reading, literal Vietnamese,
stable retries, disabled/stale revocation, read-only/current-context guards and
forged acceptance claims. Tests use explicit provider-wire/tone and identity
fixtures; they are not legal, model inference or Owner acceptance.

The optional `--narration-rights` addition to the local storyboard rehearsal
requires `--local-tts --narration-preparation --trend-radar`. It retains genuine
installed local model inference and FullQC while legal/market/research/idea/
human approvals remain fixtures. Dry-run publishing has no remote post ID.
Explicit fixture analytics/winner/learning stays synthetic; one publication is
insufficient for ranking adjustment. Revocation blocks a separate pending
approval, while historical analytics stays immutable. Both databases, publication
and analytics tables, exception receipts, physical artifacts and independent
bridge evidence participate in exact backup/restore/restart checks.

Official authorized publication/analytics/channel history, independent rights,
human speech/browser/non-developer/Owner acceptance, semantic Vision, full final
A/B/C and production deployment remain separate program requirements. The index
`north-star/native-narration-rights-evidence.json` and wave report record completed
checks, failed attempts and their precise acceptance boundaries.

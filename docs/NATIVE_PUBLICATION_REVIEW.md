# Native publication review

Native Studio now prepares and persists distribution metadata against the exact approved final video. The Video review stage has title, description, caption, hashtags, privacy, schedule, platform, validation, separate Owner approval, cancellation, dry-run execution and paginated history. Its default remains the shot-based canonical workflow. A capability flag loads the panel only on supporting Native servers. This increment implements dry runs for YouTube, TikTok, Instagram Reels and Facebook; Native live transport remains `NOT_CONFIGURED` and `publish_enabled=false`.

The existing workflow SQLite database gains two additive tables: immutable publication snapshots and content-free delivery events. Request idempotency is scoped to workspace and project. Each snapshot binds project revision, frozen render job/timeline, final bytes and SHA256, final human review, shared platform/rights validation and the capability manifest hash. Changed revisions, reviews, files or manifests invalidate a pending approval. A changed manifest also requires restarting the service before preparing new requests. Concurrent Native writers use the existing immediate transaction; the only admitted provider is the pure shared mock provider. Successful dispatch replays one stored receipt, with no remote post ID, URL or external action. A restart restores exact history.

`GET /api/projects/{project}/publications` accepts `limit=1..100` and a workspace/project-bound keyset cursor. Detail reads bound events to 100 and report truncation. POST to the collection requires editor permission; POST to `{publication}/approve`, `/cancel` or `/dry-run` requires Owner management permission. Existing session, CSRF, same-origin and database/root workspace bindings apply before request-body processing. Audit actors come from the authenticated principal. The approval acknowledges dry-run execution only and cannot authorize live publishing. Schedules require an explicit timezone, normalize for due-time comparison, reject coerced numeric dates and cannot be more than 365 days ahead. Cancellation cannot revive a completed publication.

Rights are checked for enabled canonical clips using registered asset provenance. Unknown and owner-attested rights block by default. This increment supports source-footage render binding. Generated voice/model provenance and thumbnail publication binding remain explicit blockers; an existing boolean upload confirmation does not establish ownership or grant a legal override. The shared manifest currently maps portrait 1080x1920, landscape 1920x1080 and square 1080x1080 profiles. Other dimensions remain blocked. Platform mock validation is not official platform acceptance.

The UI renders metadata and evidence through text nodes, binds late responses to the selected project/revision/render/review and uses a stable idempotency key for a repeated intent. Saved project edits remain versioned and invalidate existing production approval. History reads do not dispatch or collect analytics. A cancelled intent replay stays cancelled; preparing another identical intentional publication currently needs a different request key through the API. Native live publishing, official credentials/operator integration, analytics/channel/winner/learning UI, full profile variants and browser/Owner acceptance remain open.

The fresh `native-publication-render-n1` rehearsal generated a synthetic testsrc2/tone source, used a saved ASR fixture, rendered a 9:16 effects preview and final video, and passed the actual local full media QC. `native-publication-contract-n2` then exercised 23 authenticated Native HTTP requests: explicit mock final review, four requests with duplicate replay, separate mock Owner approvals, four dry runs with dispatch replay, two history pages and exact fresh-process restoration. Final/source hashes and canonical project state stayed unchanged after the fixture review. Fixture ownership is explicitly marked only for newly generated test media. This is local-real rendering and mock publication evidence; it does not certify speech ASR inference, real rights, external publishing or Owner UAT.

The failed first rehearsal account had membership in the wrong fixture workspace; its evidence folder/log remains intact. The initial full Native suite also detected the existing exact capability assertion missing the two new flags. That fixture assertion was updated without removing prior capabilities. Focused tests additionally cover strict acknowledgments, no-live inputs, corrupt snapshots/receipts, manifest drift, altered approval, schedule/cancel, concurrency, scoped pagination and authorization-before-body. DOM tests cover escaping, stale responses and explicit approval. These checks do not prove 1366/1920/2560 browser usability.

Source/test/evidence hashes and exact results are indexed in `docs/north-star/native-publication-evidence.json`. All accepted Phase 8–10 media and the accepted live checkout remain preserved. No live migration, provider credentials, paid operation, external post, main merge or production deployment is part of this increment. `PUBLISHING_READY`, `AUTO_EDIT_MODE_READY` and `IMPLEMENTATION_COMPLETE` remain `NO`.

# Signed Native finite publication queue controls

Wave 9 connects the existing finite queue kernel to Native signed routes, the single Runner and Studio's shot review shell. Queue execution remains disabled by default. The independent `--enable-official-publish-queue` runtime flag requires human authentication, the protected session directory and an explicitly enabled protected publishing registry. Constructor-only injected factories must be mock transports. Missing/unchecked runtime gates are refused before socket allocation. No accepted runtime was enabled.

Signed routes:

- `GET /api/connections/official-publish-queue`: gate status; no decryption, token, session URI or authority grant.
- `GET /api/projects/{project}/official-publications/{publication}/queue`: bounded scoped history, 1–100 rows and workspace/project/publication-bound cursors.
- `GET .../queue/{plan}`: qualified history and typed per-step results.
- `POST .../queue`: strict separate finite Owner plan approval. It stores a policy and wakes the Runner; the HTTP handler sends no provider request.
- `POST .../queue/{plan}/cancel`: local future-plan stop. It preserves the publication grant and known history, including after source edits. Completed plans remain unchanged.

GET responses use `no-store`. Current Owner and CSRF are enforced before mutation bodies are read. Client tokens/endpoints/mode/runtime flags, numeric acknowledgements, invalid bounds, scope/cursor/key conflicts and wrong hashes are rejected. History remains available to readers. No generic tick route or browser publishing is added.

The Runner recovers publication-worker intents before queue claims, then starts its thread. Each due call performs one bounded queue operation through the original guarded worker; no early call runs the next step. Existing media/analytics/account/core work continues if the queue is disabled or unavailable. Uncertain wire outcomes, changed authority/source/configuration, expired window/grant and exhausted limits retain the kernel's review stops; no automatic renewal or second initialization is introduced.

Studio provides explicit runtime read, device-time start/deadline normalized to UTC, finite step/interval limits, separate acknowledgement, scoped history, stored-plan read and cancellation. It uses the selected publication's current saved snapshot/dispatch/grant binding. The Owner must read the publication state first. Creating a plan does not send an extra manual step. Unknown creation outcomes retain the exact request key. Scope/role/project/grant changes discard late responses and reset draft acknowledgement. Historical plan cancellation remains available after edits/archive/analysis; publication-level “Dừng quyền gửi” revokes all publication authority. All strings use text nodes, mock results retain their qualification, and initialization performs no request. Cards reuse the original shot review shell.

# Native analytics history and review

The Native Studio Video stage now has a capability-gated analytics panel. It reads saved publication requests, per-video metric history, a chronological comparison, assessment factors, frozen render features and recommendation-only insights. A bounded workspace overview selects the latest recorded observation for each distinct publication. It explicitly reports that the channel account is unverified and account totals are unavailable. The panel performs no sync on page load, history read or project selection.

Native uses the existing provider-neutral analytics models, deterministic fixture provider and scoring/insight functions. The fixture provider no longer imports the API database solely to obtain UTC time; it imports without FastAPI, SQLAlchemy or GPU packages in the locked Native runtime. Three additive workflow tables persist sync intents, immutable metric/feature/assessment/insight snapshots and content-free events. Shared normalized metrics preserve unsupported values as null. Collected timestamps are aware UTC. Exact publication snapshot/receipt/approval, request fingerprint, frozen render job/timeline/final SHA and source evidence remain bound. A later project edit does not backfill old video features or overwrite observations.

GET `/api/analytics/providers` returns explicit provider availability. GET `/api/projects/{project}/analytics` accepts `limit=1..100`, a workspace/project/publication-bound keyset cursor and an optional publication ID. Detail reads at `/{sync}` include bounded events and the immutable observation. GET `/api/analytics/overview` pages the latest recorded fixture for each publication using a workspace-bound cursor. Neither overview nor per-video reads invent channel totals, coverage dates, missing ratios or publication times.

POST to the project collection, `/{sync}/process` and `/{sync}/cancel` requires Owner management permission plus the existing authenticated session, CSRF and same-origin checks. Authorization runs before reading the body; audit actors come from the verified principal. Default mode is official. Native official collection remains `NOT_CONFIGURED`: it lacks the independent configured account/read consent and a completed authorized live publication. An official request saves that unavailable state with no snapshot and never falls back to fixture metrics.

Fixture requests require both an explicit named fixture profile and a strict true acknowledgment. Their observations always identify `fixture://` source, `mock=true`, `external_call=false` and `real_audience_observation=false`. They have no remote post ID or provider-posted timestamp. The UI defaults to official/unconfigured mode and places fixture controls in an explicit sample-data section. Fixture assessment uses the existing absolute reference algorithm; its evidence says that a channel baseline is unverified. It cannot establish real winner or learning acceptance. No delete, budget change, media edit, publishing or recommendation application occurs.

Initial, manual and one-shot scheduled fixture syncs persist distinct requests. Schedule dates require an explicit timezone and cannot be more than 365 days ahead. Rate limits retain provider Retry-After and exponential backoff, stop after three attempts and preserve no metric snapshot on failure. Cancellation cannot revive a completed job. Request replay, concurrent workers and process restart retain one observation per sync. Snapshot insertion, terminal status and completion event share a savepoint so a completion failure rolls back the observation. The UI holds an idempotency key for retries; the explicit “Chuẩn bị quan sát mới” action prepares a new manual observation without calling a provider or granting acknowledgment.

Feature extraction uses the published render job, never current project labels. Unknown semantic hook/niche/strategy/voice/music labels remain null. Source subtitle selection now saves its versioned template reference in canonical metadata; earlier renders without that reference keep the ID unknown and retain the exact frozen style as evidence. Historical schedule/create time is not substituted for actual provider posting time. Production cost stays null because this fixture path has no billing receipt.

The `native-analytics-contract-n2` rehearsal made 26 authenticated loopback requests against an owned copy of the preserved synthetic playable source render. It recorded four insufficient-data fixtures and one later normal fixture, retained earlier history, paged six intents and four latest distinct publication observations, verified official unavailability and restored exact state in a new process. Publication history, canonical project and media hashes stayed unchanged. The first run failed only while exporting the summary because a Windows path used backslashes; its observations and failed evidence remain intact. The fresh copy reset only fixture analytics rows; no live database or accepted media was used or replaced.

The additional `native-analytics-restore-n3` rehearsal created a checksum-anchored offline backup and restored all five observations, six sync intents, four publication records, events, project history, configuration evidence and final media bytes to a fresh owned directory. It found and repaired an actual Windows staging-path failure: guarded extraction uses extended Windows syntax only for IO after normal containment/link checks. The archive path validation and trusted checksum remain mandatory. Backup metadata now counts Native publication/analytics tables and refuses queued/scheduled/retrying work before snapshotting. Existing absolute render-result paths are not rebound; rendering after restore and production recovery acceptance remain separate gaps.

Focused Native, HTTP/RBAC, backup and DOM checks cover missing values, history/replay, frozen features, schedule/backoff/cancel, scope, corruption, concurrency, savepoint rollback, stale UI responses, explicit acknowledgment, new-observation preparation, no-live fallback and long-path extraction. Exact counts, source/evidence/log hashes and failed attempts are in `docs/north-star/native-analytics-evidence.json`. The shared API regression and prior full Linux regression are indexed separately. DOM tests do not certify actual browser or Owner UAT.

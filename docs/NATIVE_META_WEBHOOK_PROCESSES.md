# Native Meta delivery across independent local processes

Actual loopback HTTP now carries qualified Meta winner/learning/projection events to a separate receipt process. The existing durable Native outbox, operator selection, signing, lease recovery and attempt audit are reused. Provider/identity/publication/nonplayable-media inputs remain explicit synthetic fixtures. This is local-real delivery evidence, not genuine Meta analytics, an actual Agent Hub, real production HTTPS or Owner/video acceptance.

The recipient uses only standard library HTTP/SQLite, the public versioned event schema and external jsonschema. It imports no Video Factory application packages and cannot read the workflow/intelligence DB. It validates HMAC, timestamp, body digest, event/idempotency identity, workspace, JSON Schema with date-time checking and explicit mock flags before writing its separate receipt ledger. Every accepted unique ID retains its immutable body SHA. Same ID/different correctly signed content gets409; a bad signature gets401. Signature headers use agent-hub-bridge.v1 wire authentication; the signed body is agent-hub-qualified-feedback.v1. These independent version identifiers are retained rather than rewriting old contracts.

The producer runs in fresh native processes, recreating existing readers from the owned workflow root with missing credentials and provider/DPAPI access prohibited. Actual Owner HTTP selection binds each immutable envelope/destination and acknowledges fixture mode. The fixture transport performs real local HTTP while keeping production HTTPS allowlisting, TLS/public-address restrictions and Owner enablement unchanged. Its destination digest includes the local fixture endpoint, so restart must retain the same port. No arbitrary private production endpoint is enabled.

Four scenarios run for each platform:

- Normal: all four Instagram or three Facebook winner/learning/projection events receive schema-valid204 receipts. Bad HMAC and a re-signed body conflict are rejected; core project/cost state is unchanged.
- Lost reply: the recipient commits once and closes the socket without a reply. Its process is stopped and restarted at the same endpoint from its own ledger. A fresh producer rotates the fixture signing key and retries the same event/body/idempotency key; the receipt is deduplicated and acknowledged once.
- Producer interruption: after a real204 response, the fixture producer actually exits71 before saving completion. Another process recovers the expired120-second lease. The receiver returns the existing receipt; the first attempt is marked response uncertain and the second succeeds without a duplicate event.
- Rate limit/offline: a429 with Retry-After40 delays the next wire attempt; an early fresh process performs no request. The due attempt succeeds. After the recipient stops, another selected event records transport unavailable/retry scheduled while core project creation still succeeds without render/provider/publishing jobs.

The final evidence consists of eight accepted scenario records and receiver ledgers: six unchanged successful cases from the initial full batch, plus both repaired restart cases from a targeted rerun. The initial full batch was6 PASS/2 FAIL; the targeted repair rerun was2 PASS. It is not reported as one green eight-test batch. Five existing default-off, retry, Owner HTTP, destination/TLS wire and offline-worker guard tests pass. Production HTTPS wire checks remain mock-tested. No Studio/source UI changed, so prior browser evidence is retained rather than counted as a new current run.

Retained preflight failures were helper mistakes: omitting the required fixture human verifier, then placing a missing-secret path above the owned data root, which the existing isolation guard correctly refused. The initial batch restart failure used a new port and was correctly rejected by destination binding. Fixtures now keep the secret directory separate and resume the same recipient endpoint; no production guard was weakened. Failed outputs are retained and are not accepted evidence.

All new process roots are owned TemporaryDirectory lifecycles and clean up after export. The exported small JSON/SQLite receipts retain no real keys, cookies or media. Prior blocked cleanup targets and accepted artifacts are untouched. The existing synthetic dataset is an explicit acceptance input; set VF_META_FEEDBACK_TEST_SOURCE to an output of scripts/north_star_native_meta_winners.py. On Windows the receiver uses the existing WSL jsonschema runtime, configurable with VF_BRIDGE_RECEIVER_PYTHON/VF_BRIDGE_RECEIVER_DISTRO. This is a local test runtime, not a production storage/runtime dependency or self-contained CI deployment claim.

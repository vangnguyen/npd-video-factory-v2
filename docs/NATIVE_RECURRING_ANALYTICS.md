# Native recurring analytics and runtime profile

Wave 10 / 7 adds bounded recurring collection to the existing Native analytics queue. It reuses the pure API report-policy model, Native retry/backoff, immutable snapshots, metrics, frozen render features, winner assessment and recommendation-only learning. It does not start external collection or enable publishing.

## Policy and controls

`native-analytics-refresh-plan-v1` freezes a publication, versioned runtime AnalyticsProfile, channel reference/selection digest from the published render request, collection policy and original configuration digest. The channel's existing `AnalyticsProfile(enabled=false)` is preserved. Explicit fixtures use the distinct `native-recorded-fixture-analytics@1` runtime profile; official intent uses `native-official-analytics@1`, `NOT_CONFIGURED`, and no external dispatch. Missing metrics remain null. Real audience observations and costs are not inferred.

Policies default to disabled. An Owner must acknowledge fixture data and read-only recurring execution to enable a fixture policy. Schedule fields require an aware first time, integer intervals of 1–168 hours and 1–365 maximum runs. Shared official-query architecture validates fixed dates or rolling complete UTC days; Native official collection remains unavailable. Saving disabled official intent is allowed; enabling it is rejected without fixture fallback or a sync job.

`GET /api/projects/{id}/analytics-refresh` provides scoped cursor pages of at most 100; `GET .../{narp_id}` provides bounded immutable occurrences and audit events. Owner-only POST creates a policy, changes its state using `expected_revision`, or admits due project work through `/tick`. The tick accepts no client time or actor. RBAC runs before body consumption; CSRF, authenticated actor, no-store responses and project/workspace scopes are retained.

The single Native worker admits at most 20 due plans per tick and processes existing analytics jobs. Each occurrence and queued sync commit atomically. One pending/retrying occurrence per plan prevents overlap. Missed periods create one current collection and record skipped slots; the next due time starts from admission. Run count measures occurrences admitted, not successful provider responses. Retry attempts remain within one occurrence and use existing bounded backoff. Maximum runs stop further admissions. Disabling or changing policy revision cancels pending/retrying work; completed snapshots remain immutable. Invalid publication/profile/occurrence bindings fail closed. Each service restart installs the same admission fence, and restore preserves policies, occurrences and events.

Studio adds a capability-gated Vietnamese policy panel, explicit default-off creation, read-only history/profile details, maximum-run/interval fields, fixture acknowledgment, revision-bound enable/disable and queue admission. Selecting/read/redraw actions do not create work. Late project/publication results are discarded. Browser/non-developer and Owner acceptance remain separate from DOM tests.

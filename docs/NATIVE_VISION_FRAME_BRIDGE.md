# Native frame input for structured Vision

`NativeEvidenceFrameExtractor` reuses checksum-bound PNG samples already produced by the accepted Native CPU analysis. It implements the existing structured API Vision extractor protocol. It makes no provider call and grants no paid, human or background authority.

The bridge binds the project, ingested asset checksum/magic/metadata, original observation checksum, exact ordered frame references/timestamps/PNG and decoded RGB hashes, saved scene records and transcript-version reference. Paths remain inside the owned state; links, hard links, corrupt frames, unexpected PNG dimensions/animation, unbounded payloads, nonfinite intervals and altered source/configuration fail closed. Physical source and frame checks run before and after extraction. Frame count remains the existing one-image/eight-video bound. No new FFmpeg decoding or source/timeline mutation occurs.

Original ingested source metadata is retained separately from actual PNG input metadata. A 3840×2160 ingested image can therefore use its already measured 480×270 sample without relabelling the original asset's dimensions. The adapter receives the actual image input dimensions and the original source checksum; frame references keep their original Native provenance. Native still records requested FFmpeg seeks, with decoded presentation timestamps unavailable. This primitive does not claim continuous tracking, whole-video freeze detection, semantic inference or calibrated confidence.

The reused OpenAI structured adapter's prompt now describes any content niche, preserves Vietnamese typography and explicitly limits conclusions to sampled frames. Its model, structured output schema, token/cost envelope, endpoint and central authorization architecture remain unchanged. Mock tests use technology, cooking and real-estate labels through the same adapter. Mock structured output cannot be relabelled as actual detections or paid invoices.

The retained rehearsal uses a synthetic owned 4K image and two-second video, two actual CPU sampling jobs, nine actual PNG samples and two explicit HTTP mock responses. It verifies exact sent bytes/reference mapping, unchanged projects/timelines, old fixture and NOT_CONFIGURED history shapes, backup/restore and a fresh process. Provider capability declarations remain recorded separately from actual mock transport behavior and unknown genuine cost.

This closes the Native input boundary only. The current Native official Vision path still remains NOT_CONFIGURED. Current Owner/rights/budget admission, protected configuration/credentials, durable paid-operation/cost outcomes, structured-result persistence, Studio review and planner/QC integration remain open. Real model pixel inference, continuous tracking, decoded timestamps, genuine B-roll relevance and Owner/browser acceptance require separate evidence. No real key, paid call, publication, GPU operation or production deployment is performed by this rehearsal.

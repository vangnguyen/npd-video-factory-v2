# Atomic canonical service outcomes and source event outbox

For project creation, canonical timeline mutation, render queue creation and successful publication finalization, the canonical repository now writes the service response receipt and an immutable versioned outcome event in the same existing database transaction. If the process exits after that transaction, the next exact signed request reads the stored outcome rather than dispatching another mutation. This closes the commit/reply gap for these four root kinds. It does not claim all Master commands, worker terminal events, outbound delivery, Native parity or full North Star acceptance.

The new provider/database-free service_outcome_context hook binds one expected root kind and an outcome writer during an authenticated command. Unrelated repository actions ignore it. Each canonical repository flushes its own state, derives its real DTO and invokes the writer before committing. The writer verifies workspace/project against the reserved operation, writes its normalized response/hash/status and creates the service_outcome_events outbox row. A failed outbox write rolls back the core change and receipt together. No Hub API, network, Redis or process is needed to commit. ContextVar tests run a service request beside an unrelated human/core write and show only the service outcome is captured. Existing human/core callers have an inert hook and do not acquire a service role or outbox event.

The existing outer response completion verifies a receipt already saved by the canonical transaction instead of overwriting it. Project creation freezes the captured DTO for service callers so a SQLite post-commit refresh cannot change its timestamp representation; legacy callers keep their previous refresh behavior. Exact durable replay returns the original receipt. Other commands that do not yet have a canonical hook retain the uncertain/no-redispatch fallback, which is tested with project-version creation. Source changes after the command do not cause another mutation. The existing render queue recovery remains separate from HTTP response recovery; additional queue/worker/terminal-event verification is still required.

The new public contract is agent-hub-service-outcomes.v1. It emits service.operation.completed, which means the covered canonical API mutation committed. A queued render is not called video.render.completed, and a dry-run publication is not called a real published video. Payloads contain IDs, source kind, actor, bounded canonical references and the response SHA; they exclude project names, prompts, scripts, manifests, provider/human tokens and full private response bodies. Status/mode/mock/external-action references remain explicit. Delivery is disabled; this work does not send new outcome webhooks or contact Agent Hub.

Signed GET /v1/operation-events requires the exact workspace and original service identity. Pages are bounded and check the action's current capability. Every returned event is rebuilt against the original succeeded operation, response digest, source kind, references, actor, timestamp and deterministic event ID. A forged actor with a newly calculated envelope SHA is rejected. Contract discovery advertises the new event version and disabled delivery. The JSON Schema is validated with date-time checking; nullable current_version_id preserves a new draft project's actual missing version.

# Signed Native receipt-bound analytics controls

Wave 10 connects the existing official analytics kernel to signed Native HTTP, the single Runner and Studio's shot review shell. `--enable-official-analytics` is independently disabled by default. Enabling it requires human authentication and an explicitly enabled protected read-account registry. Constructor-only injected factories must use mock transports; unsafe enablement and malformed protected registries are rejected before socket allocation. Loading a registry does not decrypt a token. No accepted runtime was enabled.

The routes are:

- `GET /api/connections/official-analytics`: bounded public read-account/runtime states; Owner permission is required.
- `GET /api/projects/{project}/official-analytics/source/{publication}`: qualified completed receipt binding, including the server's canonical receipt SHA256. This grants no read or publishing authority.
- `GET /api/projects/{project}/official-analytics`: scoped history with limits of 1–100 and workspace/project/publication-bound cursors.
- `GET .../official-analytics/{sync}`: stored consent and qualified nullable result.
- `POST .../official-analytics`: strict separate current-human Owner read consent. The handler stores it, reads the local journal and wakes the Runner; it performs no provider call. Exact-key replay returns the same qualified completed result.
- `POST .../official-analytics/{sync}/cancel`: local stop, exact replay and historical cancellation. It performs no remote action or provider call.

All responses use `no-store`. Mutation permission and CSRF are enforced before body consumption. Tokens, arbitrary endpoints, runtime flags, numeric acknowledgements, invalid bounds, extra fields and conflicting request keys are rejected. Readers may review historical results and the completed receipt binding. Consent does not depend on later edits to the current project; it binds the immutable published source. Neither project approval nor publication approval starts analytics.

The Runner recovers the existing store/account/publication/queue journals and analytics claims before starting its thread. A due analytics operation performs one finite collection attempt through the kernel: fresh authenticated channel proof, exact video ownership, then a fixed video-filtered report. Known provider backoff is honored; retries require the original explicit finite acknowledgement. Unknown outcomes and interrupted claims remain review stops. Disabled or failed analytics does not stop ordinary Video Factory jobs. Structured telemetry includes fixed stage/provider names and scoped sync/project IDs without content, tokens or private URLs.

Studio adds a card in the existing shot review shell. The Owner selects a completed publication, explicitly reads its server receipt binding and read-account configuration, chooses report dates, acknowledges read-only access and, when applicable, protocol mocks and finite retries. Dates start blank; they are report dates, with no unsupported timezone or reporting-coverage assertion. Each UI request lasts at most 15 minutes or the current authority's earlier expiry. Server consent remains authoritative.

Initialization makes no request. Account, source and result controls use text nodes. Scope/role/project/publication changes discard late responses and reset draft acknowledgements. Unknown create outcomes retain the exact key, including when old history was selected and a new-read draft was prepared. Completed exact-key replay displays its stored result. Historical cancellation remains available after current project edits/archive/active work. Fifteen metric cards preserve zero and `null` distinctly, display seconds/VND/ratios with explicit units, and qualify protocol mocks as having no real audience observation. Result queries, receipt/remote IDs, source hashes, mock flags and scope must agree; unsupported metrics, publication time and observation coverage are never invented. There is no polling, recurring authority, fixture fallback or publishing control in this card.

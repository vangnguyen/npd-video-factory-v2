# Native media source and rights review

The declaration behavior below remains unchanged. A separate, default-disabled [Owner exception workflow](NATIVE_OWNER_RIGHTS_OVERRIDES.md) now records scoped decisions without verifying rights or authorizing publication. It does not add override fields to the declaration DTO.

This is a versioned human declaration workflow, not provider verification or a legal override. The Assets stage exposes it when `native_rights_review=true`. Reading is explicit and permitted to viewers; saving requires the existing Owner `manage` permission, session, same-origin and CSRF checks before the request body is consumed.

New Native image/video and music uploads, including the legacy image endpoint, record their actual `source_type=user_upload`, `provider=native-local-upload`, opaque `upload://` reference, `rights_status=unknown`, nullable license and empty generation provenance. The intake acknowledgment records a user statement. Existing asset metadata is not silently rewritten when read. It does not acquire a license from a filename, extension, checkbox or model output.

`GET /api/projects/{project_id}/rights` returns `native-rights-review-v1`, the exact project revision, current source metadata and the latest declaration for each normal/legacy/music asset. `POST /api/projects/{project_id}/rights/{asset_id}` accepts a strict declaration bound to that revision and physical SHA256. It requires an explicit acknowledgment, claimed source/right, optional public license/provider/source reference/creator/attribution and an idempotency key. Licensed claims require license, provider and reference. Credential-bearing references and executable URL schemes are rejected; references are never fetched. Clients cannot supply a verification flag, effective rights status or Owner override.

Each declaration records `native-rights-declaration-v1`, workspace, project, exact asset/hash, identity-derived actor, UTC time, request and digest. `verified=false` and `owner_override_recorded=false` are mandatory. A restricted claim has effective status `restricted`; all other claims remain `unknown`. Declared source/provider/license remain inside the human request; the physical asset's actual provider/source/generation metadata is preserved. The workflow changes metadata only, invalidates project approval, creates a new immutable version and emits a content-free approval-required event. Earlier render snapshots and physical bytes remain intact.

The additive `native_rights_requests` table stores frozen request/receipt digests. Identical retries return the original receipt before checking the current revision, even after a later restriction. Changed requests conflict. Replay requires the matching immutable version and record; malformed, duplicate, foreign-project/workspace, corrupted or detached asset bindings fail closed. New declarations reject archived/busy/stale projects, changed bytes and histories exceeding 200 entries. Document, version, receipt and event commit together. Derived projects drop another project's declaration receipts while retaining physical restrictions; they require their own review.

The Studio form uses literal text, explicit read/save, a stable lost-reply key, exact workspace/project/revision guards and an acknowledgment that saving requires review again. Read-only, dirty, active-job, archived and busy states disable mutation. The result does not grant publishing permission. Unknown or restricted rights remain blocked by the shared publishing gate. The existing immutable-render revision guard also blocks a previously approved publishing intent after a declaration changes the project; no weaker dispatch path was added.

The local rehearsal in `native-rights-contract-n1` clones the prior checksum-anchored synthetic playable bridge bundle into `C:\vf-native-fixture-rights-01`. It executes 15 authenticated HTTP requests, two unverified declarations, role/override/stale guards, frozen replay and a blocked publishing intent. Old jobs/versions, other projects, source/final/preview bytes remain unchanged. New-process and fresh-root offline restore into `C:\vf-native-fixture-rights-restore-01` reproduce declarations, receipts and events exactly. The original parent and accepted artifacts are untouched. No media was rerendered, no real credentials were read, and no external provider, Hub, paid operation, publication, Owner UAT or deployment occurred.

Provider-backed license evidence, approved stock intake, explicit Owner legal override architecture/review, generation provenance and full music metadata/rights remain open. This increment does not certify MEDIA_INTELLIGENCE_READY, GENERATIVE_MEDIA_READY, PUBLISHING_READY, non-developer/browser/viewport usability, Owner acceptance or the original Mode A/B and full A/B/C bundles. Source/test/evidence hashes and exact verification counts are indexed in `docs/north-star/native-rights-evidence.json`.

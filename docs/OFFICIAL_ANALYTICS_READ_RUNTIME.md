# Scoped official analytics reads

Wave 10 now has explicitly installed YouTube Analytics and TikTok Display API read adapters. The default factory stays `not_configured`; references or enablement flags alone do not instantiate a client or acquire credentials. Configuration, mock contract acceptance, real provider acceptance and production deployment remain separate.

`OfficialAnalyticsRuntime` installs a scoped factory into the API or worker's existing `AnalyticsProviderRegistry`. It needs the existing analytics/publication repositories, current settings, a fresh public target lookup, a dedicated read-only credential resolver and `AnalyticsHTTPClient` instances. Install the same configuration independently in API and worker processes. No provider object, token or process memory is shared with Agent Hub. Automatic deployment-profile bootstrap remains unfinished.

Both the global provider gate and `analytics_external_execution_enabled` must be true. CI/test Settings reject external analytics. The bounded transport defaults to disabled; only explicit `httpx.MockTransport` injection permits mock execution. Publishing enablement grants no analytics credential and analytics grants no publishing authority.

Real transport additionally requires an explicit trusted per-project cost-policy callback and an enabled analytics provider registry entry. That callback must retain the Owner's project cap; an omitted callback makes a real runtime not configured. Mock tests may retain unknown estimates without activating a network request.

Each read requires an exact published live receipt, workspace, project, publication, platform, provider and account/profile/configuration binding. The target and receipt are checked before every request and again before accepting metrics. Mock publication receipts can enter only a mock transport. A real transport refuses them before allocating a network request. Credentials are resolved afresh in memory, expire with a 90-second margin, and contain only the supported read scopes. No token is stored in database, exports, request audit or URL.

For YouTube, the runtime checks the authenticated channel, checks the video's channel ownership, then queries the exact video and explicit date interval. It requests `youtube.readonly`, `yt-analytics.readonly`, and monetary read scope only when revenue is selected. The API's channel reports support the selected basic metrics. Watch minutes become seconds, average view duration is already seconds, and requested revenue uses `currency=VND`. Revenue remains a provider estimate. The adapter does not interpret average percentage watched as completion, playlists as saves, cards as generic CTR, or requested dates as complete coverage. RPM and the observed time window remain null. [Reports query](https://developers.google.com/youtube/analytics/reference/reports/query), [channel report combinations](https://developers.google.com/youtube/analytics/channel_reports), [metric definitions](https://developers.google.com/youtube/analytics/metrics).

For TikTok, dedicated `user.info.basic` and `video.list` scopes are required. The runtime verifies the authenticated application-scoped account and queries one exact owned video. Only views, likes, comments and shares are normalized. These are cumulative video counters, without an invented date interval, retention, revenue or completion rate. [Official Query Videos contract](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-query).

Missing rows and unsupported/missing fields remain null; returned zero remains zero. Headers, row counts, metric types, finite ranges and ownership are validated. Errors use fixed private codes. HTTP throttling/server failures use bounded retry scheduling; retries append a new snapshot and never rewrite history. Analytics routes use `Cache-Control: no-store`.

Atomic job claims prevent another worker from collecting an active attempt. Collection is bounded to 120 seconds; recovery requeues only attempts older than five minutes. Attempt counters fence stale completion, retry and failure writes. Every request gets a durable operation/cost intent before transport. Outcomes are separate from invoices: actual cost stays null without billing evidence. Unknown prices under a configured cap create `needs_approval` and block transport. Costs retain the analytics sync ID; generic job ID stays null rather than pointing to a fabricated job.

Features use the published render's frozen timeline, subtitle and audio versions. Current project metadata is labelled as such; it still needs a complete publication-time feature snapshot in Wave 12. Local receipt-confirmation time is retained as evidence, while unverified actual publishing time stays null.

Migration `0022_ns_analytics_reads` retains existing rows, adds nullable query/evidence JSON columns, and replaces the old blanket no-external-call checks with mock/transport consistency checks. No live database was migrated. PostgreSQL alteration is not yet rehearsed. SQLite migration refuses foreign keys enabled because a batch table copy could cascade into historical children. An offline backup/restore rehearsal, with foreign keys disabled before the transaction, is required; restore verifies every retained row and foreign-key edge before enabling them again. Destructive downgrade is refused.

The preserved `analytics-read-contract-n3` bundle clones the retained `publishing-runtime-n2` fixture database, performs two authenticated syncs, issues six official mock reads, restores the same two snapshots in a fresh process and exports eight JSON files plus the owned clone database. Its source database remains byte-identical. Existing fixture foreign-key debt is recorded unchanged; the independent migration rehearsal seeds a valid source-analysis fixture and verifies zero broken edges. No accepted video is replaced.

Still partial: Meta collectors, Native analytics integration, operator profile/credential/bootstrap configuration, scheduled channel refresh policy, channel/time-series/comparison UI, baseline-aware winner scoring and complete frozen learning features. Real authorized accounts, permissions and provider acceptance remain external. `ANALYTICS_READY = NO`, `REAL_PROVIDER_ACCEPTANCE_COMPLETE = NO`, `PRODUCTION_DEPLOYED = NO`.

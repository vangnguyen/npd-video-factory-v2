# Native qualified source events

The Native Bridge now records separately versioned events from the original official analytics collector, qualified winner assessments, saved learning snapshots and planning-feedback projections. Each event retains the original record, snapshot, result, scope and source-binding hashes. Reads and signed delivery revalidate the original receipt, response/cost, assessment, learning and projection evidence. Binding readers does not backfill existing history, enable authentication or dispatch a provider or webhook.

The existing `agent-hub-bridge.v1` envelope/schema remains unchanged. Qualified envelopes use `agent-hub-qualified-feedback.v1` with `native-qualified-source-event-v1` payloads. Contract discovery advertises both. Analytics emits `video.analytics.updated`; every assessment emits `video.winner.assessed`, with `video.winner.detected` only for an original winner candidate; learning and planning projections emit `video.learning.updated`. Sparse scores, peer counts and unsupported fields remain null. The analytics observation count means one retained report snapshot, including an empty report; it is not a view count or a qualified learning sample count.

Workflow source events share the producer transaction. Projection events share the intelligence transaction and pass through the existing durable source outbox. Capture failure rolls back the producer and its event. Historical readers reuse the workflow transaction and a read-only intelligence WAL snapshot, avoiding an inverse writer lock. No Agent Hub database, Redis namespace, package or memory is introduced into Video Factory.

Canonical JSON comparison rejects rehashed boolean/numeric aliases, altered source hashes, counts, timestamps, mock labels and scope bindings. Qualified markers cannot be downgraded into legacy events. Protocol mock winner candidates remain mock, non-audience observations with an unverified channel baseline. Events are recommendation-only, with no publishing enablement, automatic application, provider calls or real-provider acceptance claim. Historical reads work after Owner expiry, project archiving and provider removal, while still validating their original retained sources.

Studio accepts a qualified event only when the server advertises its exact contract and payload version. It validates original source kinds, references, hashes, event relationships, raw flags, nullable fields and sample counts. Details show the source state and limitations. Operator selection, consent, signing, retries and delivery remain existing explicit/default-disabled paths; no key or delivery authority comes from an event payload.

A fixture receiver loses its first reply and accepts the second attempt with the same signed body, event ID and idempotency key. This demonstrates at-least-once fixture delivery; it is not a receipt from Agent Hub.

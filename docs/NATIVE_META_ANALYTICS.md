# Native Meta media analytics and finite refresh

Wave 10 now connects the existing Meta API count readers to Native protected read configuration, receipt-bound collection, finite separately approved refresh, immutable history/cost records and Studio controllers. This is implemented and mock-tested component scope. Genuine OAuth/app/account/metric acceptance, full browser/non-developer/Owner flows, qualified winner/learning/Bridge calibration and full original Mode A/B/A-B-C/production remain open.

MetaReadAccount uses the existing AccountFactory and protected registry loader, with explicit Page, API version, Facebook login, workspace/profile/target binding and default-off read flag. The new Meta read token has a separate DPAPI prefix and entropy from both old read tokens and Meta publishing tokens. Its scopes exclude publishing. Startup only checks configured mounts; credential decryption and verification happen on explicit operations. Page/API-version changes invalidate the frozen read configuration. Existing YouTube/TikTok token/registry contracts remain readable.

Account verification has a distinct v2 read-profile journal. Meta publication-account v1 evidence remains separate and retains its original guards. Collection/consent/result contracts use v3; old YouTube v1 and TikTok v2 are preserved. The collector verifies the exact completed publication receipt, current Owner, original source/job/render hashes, active attempt and read configuration before each operation and before the final write. It then confirms Page/linked IG identity, media owner and the closed count query through the shared official HTTP kernel. No SQLAlchemy dependency is needed by this kernel in Native.

Instagram lifetime counts normalize views/reach/likes/comments/shares/saves. Facebook exact-video node counters normalize views/likes/comments. Unsupported fields, watch-time units, reporting windows and publication time remain null/unverified. Counts are not fabricated, rounded from strings or inferred from an error. Both persisted and frontend result guards bind the exact reported fields, mappings, units, availability and API version. Availability checks use the canonical metric order and remain valid when JSON object keys are reordered.

Finite refresh uses the same v3 collector, separate background-read acknowledgement, explicit aware start/deadline, interval, run and retry limits. It checks credential expiry, current Owner/configuration/source, and never renews consent or grants publishing. The Studio manual/refresh controls select the actual receipt video, hide date-range/revenue controls for cumulative profiles, require explicit mock acknowledgement, reject foreign/relabeled evidence and allow Viewer history reads without management rights.

Verification includes the new Native collection/token/configuration/verification/finite-refresh tests, the full Studio suite, pure API wire/normalization tests and the existing Native regressions. Exact counts and outcomes are recorded in the evidence index. The first Native import exposed an unnecessary API database import, which is replaced with the existing pure Meta provider mapping. Test-helper keyword duplication and export-configuration mistakes were corrected; failed attempts remain in recovery. A domain export initially used a publication state wrapper instead of the public journal and exposed an order-dependent frontend guard; the passing n3 exports and captured Studio tests use the corrected shapes.

`scripts/north_star_native_meta_analytics.py` exports both platforms through actual Native domain/route DTOs with explicit mocked publication/metrics transports, manual collection, two finite refresh occurrences, cost records and owned-state archives. Its owned roots clean up after export. It does not certify signed HTTP, browser, a separate-process cold restore, real audience observations or Owner UAT. None of those gates is self-accepted. Earlier accepted artifacts and previously policy-blocked cleanup roots are untouched.

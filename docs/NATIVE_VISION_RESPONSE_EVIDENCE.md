# Complete Vision response evidence

The shared structured Vision adapter accepts an optional synchronous response observer. It delivers one bounded, typed observation after the complete response body passes transport length/encoding/size checks, before semantic parsing and client cleanup. Constructors do not invoke it. The Native protected factory forwards the callback without granting human, rights or budget authority.

The observation contains request/complete-response hashes, HTTP status, sanitized request identifiers, explicit mock transport identity and valid token usage/calculated VND cost. It excludes raw response bodies, image payloads, captions, credentials and private paths. Billing invoice verification remains raw false. Usage must contain explicit integer input, cached-input and output counts inside the configured ceilings; missing values, boolean/string/float coercion, negatives or cached counts exceeding input fail closed. Unknown usage stays null rather than assuming zero or clamping counts. Explicit reported zero remains zero. Calculated token usage is separate from verified billed cost.

The observer runs before semantic JSON/schema/frame coverage/model validation can fail. Complete response evidence and valid usage are therefore available for durable settlement even when those later checks reject the result or current Owner/configuration/source approval changes. Incomplete, oversized or ambiguously framed bodies do not produce a complete-response observation or fabricated complete digest. Observer exceptions/async callbacks/nonempty return values fail with fixed private diagnostics, known complete response hash and no retry. Evidence already retained survives later client cleanup failure; private logging context resets.

# Frozen learning features

New API-stack render requests capture a bounded `render-feature-context-v1` document and its SHA256 digest in the existing manifest. It binds workspace/project/timeline version, the explicit storyboard content version or project version available at request, linked idea/version or supplied version annotations, trend cluster, hook, visual strategy, niche, topic and CTA. Capture time includes an offset and normalizes to UTC. This is a snapshot of available metadata at the render-request boundary; it is not semantic verification of those labels or observed publication time.

Capture runs in the render-request transaction with a project lock, exact project/version scope checks and deterministic idea selection. The storyboard's explicit content version takes precedence over a later current project version. Invalid foreign content references refuse the render request. Available annotations are bounded; missing fields stay null. No complete script, raw provider payload, credential or arbitrary metadata graph is copied into the context.

Renderer evidence and the persisted manifest retain the same context. Completion refuses replacement or insertion of a different context and rolls back partial completion. New provider-audio/supporting/final assets use the frozen project version for lineage. Review approval and canonical timeline/subtitle/audio behavior remain in the existing production engine. Legacy requests without a context remain renderable with no invented source version.

Analytics reads the published final render's context. Later project/version/idea changes cannot relabel the published media's observations. Actual duration, scene, subtitle, voice, music and visual clip facts still come from that same render's saved timeline/audio/subtitle versions. SHA/scope validation rejects a changed envelope. Legacy renders keep unavailable topic/niche/hook/CTA/trend/idea metadata null instead of backfilling current project tags. Existing analytics snapshots and accepted videos are not rewritten. Official publishing time stays null without provider evidence; a receipt timestamp does not certify when a post became visible.

Studio shows the available niche/topic/CTA/music and whether labels were retained with the render or lack historical evidence. DOM regression passes; real browser and Owner UAT remain unverified.

Evidence: `docs/north-star/feature-context-evidence.json`. Five new tests cover later edits, explicit content binding, scope/hash validation, completion rollback and legacy nulls. The selected production/publishing/analytics suite passes 26 tests. The fresh-process contract generates owned fixture render/approval/publication/analytics state, changes metadata after render admission, verifies persisted render-evidence and asset version lineage, collects two fixture observations through four authenticated API calls and restores exact state in a second process. Its media is deliberately nonplayable fixture bytes and its approval is a fixture. It certifies neither full media QC nor human/provider acceptance. Cross-video personalized recommendations, Native integration and full learning-loop acceptance remain open.

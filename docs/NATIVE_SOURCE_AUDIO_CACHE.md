# Native canonical PCM intermediate cache

Source effects previews and final renders now reuse actual local PCM audio when the saved audio computation is identical. The cache operates after the current canonical timeline and original asset checksums have been validated. Each job still stages its own source files, derives its own captions and audio-analysis records, writes its own timeline/render manifests, requires its own approval and runs its own render and QC. A hit copies verified bytes to that job's private `media/mix.wav`; renderer inputs never point at shared cache files.

The versioned fingerprint includes the full ordered source checksums, complete typed FFmpeg filter graph, timeline duration, PCM codec/sample rate/channels and actual FFmpeg executable SHA256. Trim, speed, delay, gain, fades, normalization, ducking, limiting, routing and silence affect the computation. Canvas, crop, project names and captions can reuse audio when they do not alter that computation. Current source validation runs again after preparation; a hit never permits changed or missing source media.

The namespace binds the actual data-root identity, persisted workspace and project. Registered source variants can use their master's namespace only after the immutable family record, frozen master version, catalog and every child's initial history are validated. The current member/profile/request/master binding must match that registered evidence. A copied metadata field cannot grant sharing. Generic duplicates use their own project scope. A restored root with a different path retains the old cache evidence but recomputes under a different root fingerprint.

Entry leases combine bounded thread waiting with Windows byte-range or POSIX file locking. Concurrent requests commit only one result, using a private attempt directory followed by an atomic ready-directory rename. Receipt and PCM writes are flushed before commit. Every read verifies the receipt digest, exact computation request, WAV PCM format, frame count, byte count and file SHA256. Copied output is measured and rehashed. Linked/reparse/hardlinked paths, altered receipts, bad PCM and cancellation fail closed. Corrupted committed entries are retained and never silently rebuilt or overwritten.

Retention admits at most 512 entry namespaces and 2 GiB of committed PCM per root. Capacity exhaustion performs the current mix privately without cache insertion or automatic eviction. Lock files and unsuccessful private attempts remain evidence, outside the committed-PCM limit; operational cleanup/TTL and a total temporary-storage quota remain hardening work. No cache operation changes project/timeline/history/approval or dispatches TTS, an external provider, publication or paid work. Actual local compute cost remains unknown.

The six-format technology rehearsal uses fresh synthetic source/tone, actual local scene/frame analysis and an explicitly saved ASR fixture. One audio build supplies six effects previews and six independently approved fixture final renders: eleven hits, exact private timeline bindings and passing FullQC for all six final profiles. Separate-process reuse verifies the same receipt/PCM. Offline backup restores family/history/media/cache to a fresh root; a new process recomputes the same PCM under the new scope without changing projects or accepted final files. This does not test new rendering after restore or certify actual Owner, browser, semantic Vision, ASR or platform-provider acceptance.

The unit suite also exercises simultaneous processes, simultaneous family requests, gain-change misses, visual-only hits, source/tool/filter/duration fingerprint changes, ordinary-copy/workspace/root isolation, forged lineage, corruption, linked files, failure, cancellation and capacity bypass. Exact source/log/artifact evidence is indexed in `docs/north-star/native-audio-cache-evidence.json`. Generated media/research/Vision/stock/render-intermediate cache completion, narrated Mode A variants, full profiles and the original final A/B/C acceptance remain open. `IMPLEMENTATION_COMPLETE` and all broader North Star readiness states remain `NO`.

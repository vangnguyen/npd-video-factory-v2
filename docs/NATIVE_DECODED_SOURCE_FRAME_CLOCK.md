# Decoded source-frame clocks for Native media intelligence

This Wave 3F/4/8/15 component replaces requested seek times with measured decoder presentation timestamps for newly created source pixel observations. It does not certify real semantic Vision, continuous tracking, genuine ASR, full Mode A/B or Owner acceptance.

New observations use `native-media-frame-observations-v2`. One bounded FFmpeg decode selects the first frame and crossings of at most seven additional requested thresholds. It keeps source timing with `copyts/start_at_zero`, uses the registered video stream and no FPS filter or seek-based timestamp assignment. Low-frame-rate/VFR media can return fewer than eight samples; no duplicate frame is synthesized to fill a requested grid. Images use a logical zero-time still-image reference and claim no video PTS. [FFmpeg options](https://ffmpeg.org/ffmpeg.html#Advanced-options) describe timestamp preservation/normalization; [showinfo](https://ffmpeg.org/ffmpeg-filters.html#showinfo) exposes decoder PTS and time base.

Each video sample binds integer PTS, rational time base, exact normalized source seconds, selected ordinal, dimensions, PNG/RGB hashes and private references. A hashed clock manifest and original decoder log are checkpointed with the PNGs. Readers verify the rational clock, manifest, log, original media job/checkpoint/result and current physical source. Rehashing a project record cannot create measurement authority. Linked database/clock paths, altered artifacts and inconsistent times reject. The independent read-only SQLite connection is explicitly closed on Windows.

Version 1 observations remain readable with their original fingerprint/JSON and requested-seek label; their clocks are not upgraded or remeasured automatically. Project copies retain the original measurement files and explicit rebinding lineage. The new clock travels through mounted Vision input, official structured result, reviewed context and reviewed crop history. Measured clock verification stays separate from semantic inference, prediction confidence, rights, provider consent, billing, continuous tracking and publishing approval.

Studio labels decoded PTS, unverified historical seeks and still images separately. Source scene/pixel ranking receives actual sample times. The older dense motion/silence/ASR analysis and rendered-frame QC are separate clock paths; this component does not silently certify them or whole-video coverage.

Evidence is indexed in [decoded-source-clock-evidence.json](north-star/decoded-source-clock-evidence.json). Retained CPU-only VFR and nonzero-start source bundles include source videos, independent FFprobe clocks, observations, PNGs, decoder logs/manifests, Vision input bindings and project state. The VFR source has six actual decoded frames and four selected samples at 0, 0.44, 1.12 and 1.84 seconds. A separate source starts at container second 4 and preserves normalized sample times confirmed against FFprobe. Source bytes, timeline and approval stay unchanged. Backup restoration in a fresh process verifies both original jobs, all physical clocks and frames without new jobs/providers. Owned rehearsal roots are cleaned after export.

Failed tests are retained. They exposed an unclosed SQLite connection and a changed artifact-error ordering; both were repaired before final related checks. Genuine footage/semantic providers, dense source motion/audio clock validation, calibrated confidence, tracking/occlusion, actual full UI/Owner, original A/B/C and production acceptance remain open. No paid/provider operation, publishing, main merge or production deployment occurs.

Run `python scripts/north_star_native_decoded_frames.py --output <fresh-external-directory>` in the existing Native runtime. The script uses generated local sources and makes no ASR/semantic provider call.

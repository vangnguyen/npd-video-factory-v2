# Native qualified channel-relative winner kernel

Wave 11 adds immutable Native assessments over the existing receipt-bound official analytics journal. Assessment performs no provider call, consent renewal, publishing action, media deletion or budget change. This increment is the kernel; signed HTTP, Studio controls, learning and Bridge projection are separate remaining integrations.

`apps/api/app/analytics_channel_policy.py` extracts the existing `WinnerChannelPolicy`, weights, duration buckets, nullable factor values, counter-growth rules and relative assessment function from ORM access. Rule bodies, algorithm version `winner-channel-assessment-v1`, policy serialization/digest behavior and defaults are preserved. `analytics_cohort.py` retains the API database adapter and re-exports its existing public imports. Native can now import the same policy without SQLAlchemy, a provider SDK or the API runtime. Existing API cohort/learning tests exercise the preserved interface.

`NativeOfficialWinners` requires the exact existing official analytics kernel and pins its store/workspace/clock/root. Strict versioned requests bind a successful sync and the server-canonical result SHA256, a configurable bounded policy, explicit recommendation-only acknowledgement and, for protocol mocks, an exact Boolean mock acknowledgement. Current human Owner authority is checked before exact-key replay and again after selection before insertion. The kernel uses two additive tables for frozen assessments and events; backup records both counts. There is no queued or recurring execution grant.

The source getter and existing publication/analytics history/source readers accept an internal optional transaction connection while preserving existing calls and response shapes. One Native assessment transaction validates each selected successful analytics result, all three provider-response/cost proofs, qualified completed receipt, immutable dry-run/render job, source hashes and captured features. It does not inspect later editable project metadata, resolve credentials, consult a current provider factory or depend on expired historical consent remaining active.

Compatible peers share workspace, exact account/profile target digest, platform/provider, transport/source qualification, report dates/revenue query, known rendered dimensions/codec/fps fields, duration bucket, frozen niche and available frozen channel profile reference/hash. Unknown candidate niche/duration/dimensions/codec cannot establish a cohort. The bounded scan considers at most 500 qualified results and at most the policy's 100 distinct peer posts. The candidate's remote post is excluded; repeated results or publications for one remote post cannot inflate the baseline. Equal collection times use saved result-update time and snapshot ID to choose the latest compatible observation. Only observations at or before the candidate collection time are considered. Truncation and exclusion counts are retained.

The original policy compares supported factor values with peer medians. Defaults require five compatible distinct peer posts, at least 500 candidate views, sufficient configured weight coverage and a supported retention/completion factor. Outcomes are `winner_candidate`, `normal`, `underperforming` or `insufficient_data`; missing factors remain unscored. Engagement is compared only when supported interaction components match. Requested report updates do not become cumulative video-counter velocity; Native report velocity, publication age/time, unsupported completion/CTR/saves and unknown production cost remain unavailable. The explanation cites selected peer snapshots, medians, weights, missing evidence and policy hash.

Each saved assessment freezes candidate/peer source proofs, policy, scope, original authority, exclusion/truncation evidence and recommendations. Historical reads revalidate those exact original sources and recompute the same score from the frozen selected peers without rescanning later history. Hash, score, scope, qualification, cost, source, receipt or peer mutations fail closed. New observations do not rewrite prior assessments. Edited/archived current projects, expired current Owner authority and removed provider factories do not prevent authorized historical review; a new assessment still needs current Owner authority.

Protocol-mock assessments retain `mock=true`, `real_audience_observation=false` and `channel_baseline_verified=false`, including a synthetic winner candidate. They cannot become real audience learning. A relative assessment is a recommendation for review; compatible selected posts do not establish complete channel history, equal publication age, verified semantic annotations, causal improvement or future performance.

The existing six-role backend already supports video, audio, image, alpha PNG logo, music and Vietnamese subtitles, with durable chunks, local decoding, MIME/magic validation and same-project dedup. The previous UI created requests with `expected_sha256=null` and reused an idempotency key based on filename, size and metadata. Different bytes with the same name/size could reuse an earlier intent after a lost response. Resume checked the received prefix but could not bind the unsent tail to the originally selected file.

`native-file-sha256.mjs` now hashes the whole selected file before initializing or resuming. It reads Blob slices of at most 1 MiB, retains bounded SHA state, yields between slices and abandons hashing on pause, file/classification/rights or project-context changes. It does not allocate a whole-file ArrayBuffer or send data while hashing. The SHA-256 compression/padding follows [FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final). The existing [WebCrypto digest API](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/#SubtleCrypto-method-digest) remains used for small chunk/DTO hashes. Tests compare known vectors, padding/block/chunk boundaries and binary payloads against Node and WebCrypto independently.

New UI requests include the full `expected_sha256`; the scoped request-key cache includes it. Retries for the same exact intent reuse the key, while different source bytes get a different intent. Resume compares the full source hash before sending remaining chunks or finalizing. Completed historical nullable-SHA requests remain readable, but a substituted file cannot reuse their known completion source hash. Historical partial requests retain their original nullable contract and prefix checks; they are not retroactively described as having a frozen whole-file intent.

The history selector includes a short known source digest and Vietnamese role/status labels, distinguishing same-name files. It labels older partial intents without a known whole hash honestly. The main card shows received/total bytes and status; raw verification detail is collapsed under an advanced section. File selection changes clear the previous rights acknowledgement. Failures update the card and global message. MIME/magic failures instruct the operator to choose the correct type/MIME and start a new upload, rather than referring to an unrelated job log. User-use confirmation does not grant publication rights or enable publishing.

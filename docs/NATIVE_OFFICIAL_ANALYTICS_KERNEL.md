# Native receipt-bound official analytics kernel

Wave 10 adds a separate Native journal for read-only YouTube analytics. It reuses the existing pure provider contracts without an API framework, ORM, shared database or GPU dependency. Existing fixture analytics, publication journals, finite publishing queue and accepted artifacts remain intact. The new operator gate defaults off. This increment is a kernel; signed routes, Runner attachment, Studio, finite scheduled refresh and qualified winner/learning/event integration remain subsequent work.

`Collect` requires a completed qualified official publication receipt, exact publication/receipt hashes, an exact matching read-only account target and configuration hash, explicit calendar dates, a literal read-only acknowledgement and an exact idempotency key. A protocol-mock publication requires a protocol-mock account and a separate strict mock acknowledgement. Mocks cannot be queried through a real client or relabelled as audience observations. Owner identity is checked against the current human registry. Consent lasts at most one hour and never outlives that identity. It grants no publishing or recurring-refresh authority.

Each atomic claim records an attempt before reading. Every attempt performs the fixed authenticated channel lookup, verifies the exact video belongs to that channel, and then requests a video-filtered report. Credentials are resolved afresh before each read; current identity, deadline, workspace, claim, account configuration and frozen publication/source are checked before and after responses and inside response/snapshot write transactions. Later editable project metadata, current project revision and expired publishing consent do not rewrite the original published features. Immutable published job/source changes stop new reads. No token, raw response body or private upload-session URL is journalled or returned.

Account configuration checks in this kernel use the frozen loaded account contract. The next runtime increment must additionally detect replacement/removal of the protected read-only registry file, following the existing publishing registry fence. No accepted analytics runtime is enabled by this kernel.

Five additive tables retain sync consent, attempts, hashed sanitized response evidence, immutable observations and audit events. Each read has a distinct attempt/operation cost record, with unknown billed cost retained as null. Initial/manual collections use distinct explicit keys and append history. A scoped cursor bounds pages to 1–100 items. Completed snapshot reads need no current provider, credential or publishing grant. Backup counts and active-operation checks include all five journals. Startup recovery marks interrupted claims and their owned unfinished costs unknown, including cancellation and interrupted cost settlement; it never decrypts or automatically replays them.

Known 429/5xx responses can schedule at most three attempts only with separate bounded-retry acknowledgement. The default is one attempt. Durable delay, attempt count and original consent deadline survive reopen. Authorization failures, malformed responses, wrong ownership, changed bindings and unknown wire outcomes stop collection. Cancellation is a local idempotent stop and preserves completed snapshots. It sends no provider mutation.

The report maps seven supported counters/timings, optionally estimated revenue under the monetary scope. Watch time converts provider minutes to seconds. Empty rows and unavailable metrics remain null; zero remains zero. Requested dates do not prove complete coverage. Completion rate, observation window, CTR, RPM and exact publication time are not inferred. Estimated revenue uses VND and retains its estimate qualification. These choices follow the official [report query contract](https://developers.google.com/youtube/analytics/reference/reports/query) and [metric definitions](https://developers.google.com/youtube/analytics/metrics).

Protocol mocks use `source_kind=official_protocol_mock`, `mock=true`, `external_call=false`, `real_audience_observation=false`. The real-client architecture requires a qualified nonmock receipt, current protected read account, Owner consent and configured OAuth scopes; no real-provider acceptance is claimed here. Successful stored snapshots validate the original scoped consent, all three response proofs, their exact attempt/cost bindings, mock flags, normalized metrics and unsupported/null fields.

Verification and hashes are indexed in `docs/north-star/native-official-analytics-kernel-evidence.json`. The retained rehearsal `scripts/north_star_native_official_analytics.py` uses explicit nonplayable QC/rights/account/platform/identity/OAuth/provider fixtures. One known backoff, an approved retry, two immutable observations and a local cancelled third request produce seven fixed read requests, zero external calls, and exact restore/fresh-process replay of all twenty journals, three analytics histories, the original receipt/project/job/files and the preceding finite-queue receipt/two histories/fifteen journals. The archive excludes private vault/token files and session URLs. Genuine provider, audience, browser and Owner acceptance remain unverified. Full analytics and North Star readiness remain NO; Owner listening/UAT stays deferred.

The subsequent protected read-registry fence in `NATIVE_OFFICIAL_READ_REGISTRY_FENCES.md` closes the file-change/removal prerequisite and adds a final post-resolution Owner/source/configuration/credential-lifetime check. Signed analytics runtime/Studio integration is still pending.

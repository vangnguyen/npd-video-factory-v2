# Narrated master variants with verified PCM reuse

Wave 7 now creates explicit six-format families from a saved narrated master: YouTube 16:9, Shorts/TikTok/Reels 9:16, social 1:1 and feed 4:5. Every child starts without approval or jobs. Family creation does not infer narration, render, publish or mutate the master document. The Source Mode B family remains a separate compatible path.

## Canonical edits and evidence

`NativeNarratedVariants` freezes the master revision/document/timeline, prepared reference, typed format catalog, request fingerprint and initial child documents in one SQLite transaction. Children preserve the brand, authored scenes, measured durations, selected media and voice inputs. The frozen template changes canvas only; shot and advanced views still share the same canonical timeline. Crops are explicitly flagged for review with unknown tracking confidence. Project rights declarations, overrides, narration exceptions and planner/analysis authority are cleared or retained only as origin hashes; no master approval or legal authority is inherited.

The typed narration derivation binds workspace, master, child, original source project/job/snapshot/approval/plan/PCM and unchanged voice inputs. Resolution checks the workspace marker, immutable family/master/child history, frozen catalog and lineage, succeeded source job, both checkpoints and physical source files. It cannot be replaced by a client URL or arbitrary cross-project job ID. Nested families resolve the original PCM rather than introducing another inference. Changed narration, corrupted source files, forged scope/flags/history and unknown formats fail closed. Visual edits keep compatible PCM but invalidate the current preview and approval through existing editing rules.

Exact-key retries recover the original family after a later master edit. A changed request with that key conflicts. Concurrent retries produce one family, and failure during a later child creation rolls back every child/event/batch. History uses bounded workspace/master cursors. Backup includes the additive family table, original source artifacts and both existing databases.

## HTTP and Studio

Authenticated GET `/api/narrated/variant-profiles` returns the six profiles. GET `/api/projects/{id}/narrated-variants` returns scoped history and a current master binding; editor POST explicitly creates selected formats using expected revision/timeline/reference hashes and a request key. Viewer reads remain available; mutation requires editor authority and CSRF before body processing.

Narration history/audio now run behind the shared HTTP authentication boundary. A child audio URL resolves only its verified current derivation. The derived review projection retains the original plan's project/job identity and provides a child-scoped audio URL; it does not impersonate a child inference. Source application remains same-project only. The reuse receipt and rights projection identify the original project and derivation hash without transferring approval or rights. Existing unmodified preparation/reuse outputs stay compatible.

Studio offers explicit format/history reads, selection, creation, opening a child, literal source text and stale/permission/active-job guards. It issues no automatic provider/render/publication action. Each child must generate a fresh audible full-effects preview, review it and obtain its own production/final approval. The shared Native request adapter now accepts the two existing panel calling conventions: plain domain bodies and bounded POST fetch options. This fixes the newer narration, rights and planner panels sending an options wrapper as the domain body. Credentials, CSRF and method remain controlled by the app.

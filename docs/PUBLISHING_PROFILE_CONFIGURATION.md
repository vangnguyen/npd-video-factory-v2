# Versioned publishing profiles

`PublishingProfile` and `PublishingProfileCatalog` define public server configuration independently of the production engine. Each profile carries a scoped versioned target, the platform's official provider key, optional YouTube category/kids/synthetic disclosures, a nullable budget and nullable per-operation estimates. OAuth tokens, encryption keys and secret references are rejected as profile fields; existing external credential custody remains separate.

The registry resolves the latest version of an exact workspace/profile pair. A workspace with multiple channels must select a profile explicitly. There is no foreign-workspace or other-platform fallback. Existing versions cannot be removed or rewritten when replacing a catalog; new versions are additive. Resolution returns copies, so a caller's mutable estimate dictionary cannot alter stored configuration. Canonical serialization prevents dictionary ordering from rewriting history.

A target's credential configuration fingerprint describes a public configuration revision and never token bytes. Changing credential routing requires an updated public binding revision and profile version. Configured profile/account IDs do not establish official account verification. The worker still checks fresh credentials and the exact official account before mutation.

YouTube readiness requires category and explicit boolean kids/synthetic disclosures. Costs must be finite, nonnegative and exactly representable to four decimal places. Unavailable values remain null; profile estimates are configuration, not billed spend. Catalog JSON is bounded to 256 KiB and 1,024 version records. All secret/key/token lifecycle and production catalog custody remain external concerns.

Verification: 20 passing unit checks for strict validation, JSON round-trip, workspace/channel/platform isolation, revisions, immutable history, mutation isolation and malformed/oversized configuration. First run passed nineteen tests but the oversized case's autogenerated pytest ID exceeded Windows' environment-variable limit, causing setup/teardown errors. Short explicit case IDs fix the harness; the second run passes twenty with no warnings.

Remaining: configured provider/runtime registration, persistent Owner profile administration, channel/catalog UI, private credential resolver/key lifecycle and real-provider acceptance. This increment makes no provider request, approves no budget, activates no publisher and does not certify Publishing or Multi-Niche readiness.

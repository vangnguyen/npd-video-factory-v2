# Dedicated Google Desktop OAuth protocol

The shared pure protocol module now builds bounded aware authorization requests with high-entropy state, S256 PKCE and exact IPv4/IPv6 loopback redirects. It builds authorization-code and explicit refresh form requests to Google's fixed token endpoint. Analytics requests only readonly/analytics scopes, optionally monetary readonly; publishing requests upload and account readonly. It rejects mixed, broader, reduced or duplicate granted scopes under this dedicated credential policy. These contracts follow [Google's Desktop OAuth guide](https://developers.google.com/identity/protocols/oauth2/native-app).

The default token transport is disabled. Explicit mock transport is labelled as mock; live transport requires independent operator activation. HTTPS certificate verification, bounded request/response/timeouts, no environment proxy inheritance, redirects, compression or automatic retry, and context-local HTTP log privacy are enforced. Callback state and bounded fields, exact target/client/scopes/secret fingerprints, response-time configuration/transport checks, duplicate JSON, token type and aware expiry are validated. Unknown transport/results require review. Tokens, code and PKCE verifier are excluded from representations; public grant proof contains only public binding/scope/expiry fields and no account verification, publishing or production-consent authority.

An explicit refresh preserves the original refresh token when the response omits it, accepts a returned rotation, and never extends a previously known refresh expiry. Unknown refresh expiry remains null. Access expiry starts at the request time as a conservative bound; late responses do not gain a new full lifetime. Dedicated grants convert to the existing purpose-specific in-memory credential models. The existing account confirmation, publication/read consent, source/receipt, rights and cost gates still apply. Refresh does not renew those grants or enable scheduled publishing.

This increment supplies reusable protocol primitives only. Its caller must provide current human authority, durable one-use callback and operation claims, encrypted access/refresh/client-secret custody, request/cost audit and account verification. No OAuth listener, redirect route, automatic credential resolver, encrypted refresh-token custody or Studio sign-in flow is connected yet. Default Native/API account and publishing behavior remains unchanged. Those integrations continue as separate work, with genuine credentials/provider/browser/Owner/deployment acceptance still pending.

Future authorization must use an external secure browser with manual human consent, following [Google's OAuth browser policy](https://developers.google.com/identity/protocols/oauth2/policies). This implementation does not open a browser, collect a real token, revoke remote credentials or perform real publishing.

Repository evidence records the actual Native/API contract tests and four synthetic token requests for analytics/publishing acquisition and explicit refresh. Public proofs preserve null refresh expiry and the old grant's expiry; no private token/code/verifier/body appears in exports. Protocol mocks are not genuine OAuth, account, audience or production acceptance. All original North Star requirements remain in scope.

# Native explicit Google OAuth operations

The local journal adds current Owner admission and one-use operation claims to the shared Desktop OAuth protocol and private Windows custody. Construction, discovery, historical reads and restart recovery never decrypt a credential or send a provider request. The runtime is disabled by default and remains separate from the Native server and Studio until their explicit integration is verified.

An operator supplies a dedicated analytics or publishing slot with an immutable encrypted-client receipt, exact target, public Desktop client ID and approved scopes. No client secret or token is accepted through an operation request. The existing workspace binding and current human identity registry enforce Owner role, enabled token, exact identity revision and expiry. Consent freezes the project revision/document, slot/configuration, protocol-mock acknowledgement and a 60–900 second window within the Owner credential lifetime.

`start` saves a finite private state/PKCE intent and a public receipt. `authorization_url` is a separate explicit Owner action; its state-bearing URL is not written to SQLite, events or exports. A human must authorize through an external browser. The eventual signed callback integration must preserve these boundaries and must not use browser automation. Invalid state/duplicate callback fields leave the intent pending. A correctly bound denial consumes the intent without a provider request or cost operation.

`exchange` atomically consumes the authorization and creates a unique operation claim before token dispatch. `refresh` requires a new explicit Owner consent and an exact successful source result, and consumes that original grant generation once. Each token request has a distinct project-bound cost intent, with paid=false and unknown estimated/actual amounts retained as null. Cost recording grants no authority. Successful response custody produces a new immutable grant receipt; old ciphertext and public history remain intact. No active credential pointer, account confirmation, publishing/read/background consent or production authority is selected or renewed.

Before and after the wire call and private save, admission rechecks the claim, project/document, current Owner identity revision, consent deadline, operator/transport gate, slot, original private client, PKCE or refresh source. A late response cannot select a grant after these bindings change. Unknown network outcomes, rate limits, malformed token replies and interrupted operations never replay automatically. Restart marks unfinished claims as unknown, including the narrow cost-intent/link crash window. Reauthorization or a fresh explicit operation is required; a consumed code or grant cannot be retried by changing its request key.

Three additive SQLite journals contain authorizations, operations and fixed public events. Getters and bounded workspace/project/kind history verify immutable hashes, original source linkage and response-cost receipts without current credentials or authority. Backups include public journals and metadata, exclude the private vault, and refuse an in-flight claim. Recovery to a fresh root preserves public history even with private custody unmounted; explicit grant resolution still requires the separate original private files.

The rehearsal uses synthetic Owner identity, actual Windows DPAPI/private DACL/SQLite/backup recovery and an explicit HTTP mock transport. It is not genuine OAuth, account, audience, browser, Owner UAT or production acceptance. Signed Native routes, Studio controls, approved real client acquisition, credential resolver selection, account confirmation and other platform integrations remain open.

The shared protocol follows Google's official [native-app OAuth documentation](https://developers.google.com/identity/protocols/oauth2/native-app) and [OAuth policies](https://developers.google.com/identity/protocols/oauth2/policies). It keeps loopback redirects, PKCE, exact scope checks and explicit refresh handling; local consent windows and single-use claims are Video Factory safeguards.


Later component integration: [publishing-purpose credential selection](NATIVE_GOOGLE_OAUTH_SELECTIONS.md) verifies the channel and attaches an explicit resolver to the Native worker. It does not select analytics credentials, enable publishing or renew publication consent. The earlier operation milestone assertions above describe acquisition/refresh alone.
